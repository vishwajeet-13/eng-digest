## 1. Cloudflare stopped rebuilding giant DNS zones for tiny changes
*Cloudflare Blog* · Backend

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-03/1.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-03/1.mp4"></video>

**In one line:** Cloudflare now rebuilds only the part of a domain's data that changed, so updates reach its servers about twice as fast.

**What happened:** A "zone" is all the DNS records and settings for one domain. Some zones now hold more than 20 million records. Before, many small changes (like a setting) forced a rebuild of the whole zone, which was slow and used lots of memory. Cloudflare built a planner that picks the smallest rebuild it can prove is safe, and a scheduler that merges several changes for one zone into one job. If the planner is unsure, it still does the full rebuild. Before each build, it also checks fresh data from the database, because things can change while a job waits. They tested by running the new system next to the old one and comparing the results.

**Why it matters:** Peak memory fell by 85%, and the median wait from a change to being written dropped from about 7.7 to about 3.3 seconds.

**New words:** **DNS zone** — all the records and settings for one domain · **Kafka** — a system that passes messages between programs in order · **Quicksilver** — Cloudflare's store that copies data to its servers worldwide · **Full build** — rebuilding every record in a zone

## 2. How Nvidia's Nemotron AI model does more with less
*ByteByteGo* · AI

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-03/2.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-03/2.mp4"></video>

**In one line:** Nvidia's Nemotron language models mix several tricks so they use much less computer power for each word they write.

**What happened:** Normal AI models get slower and use more memory as the text gets longer. Nemotron mixes two kinds of layers. "Mamba" layers keep a small, fixed-size running summary, like short notes. A few attention layers can still look back at earlier words. It also uses "mixture of experts": the model has 128 small expert networks, but a router picks only 6 for each word. So a 30-billion-parameter model uses about 3 billion at a time. Nvidia also shrank the model from about 66 GB to about 22 GB using smaller numbers, and trained it to guess several words ahead.

**Why it matters:** AI agents call a model dozens of times per task, so cheaper answers make agents more practical.

**New words:** **Token** — a small piece of text, like a word or part of one · **Parameters** — the numbers a model learned during training · **Mixture of experts** — many small sub-networks, with only a few used per word · **KV cache** — saved work so the model does not repeat calculations

## 3. Uber built one front door for its AI agents
*InfoQ* · AI / Backend

**In one line:** Uber made a central gateway so AI agents can find and safely use more than 5,000 internal tools.

**What happened:** AI agents need to call company services, and every team was doing it differently. Uber built an "MCP Gateway" that now covers over 800 servers and 5,000 tools. A registry stores each tool's description, owner and on/off setting. A proxy turns the agent's request into the call Uber's services understand. A crawler finds tools from existing service definitions, and new tools stay off until their owners approve them. Access is checked per server and per tool, and sensitive data can be hidden in answers. Agents search for tools step by step so they do not load thousands of descriptions at once.

**Why it matters:** It shows that old ideas like gateways, permissions and discovery matter just as much for AI agents.

**New words:** **MCP** — a standard way for AI agents to find and use tools · **Gateway** — one entry point that routes and checks requests · **PII** — personal information, like names or emails

## 4. Shopify checks what is really exposed to the internet, not what the config says
*InfoQ* · Security / Cloud

**In one line:** Shopify's scanner "Overexposed" finds web services anyone can reach without logging in.

**What happened:** The first version read config files in a code repository. It gave false alarms and missed services made elsewhere. The team's lesson: the repository shows intent, but the cluster shows what is enforced. The new version asks Google Cloud's asset inventory what is really running. Then it sends one anonymous web request to each candidate and gives a verdict such as exposed, protected or inconclusive. Unclear results stay "inconclusive" rather than being called safe. This cut inconclusive results by about 80%. Because the scanner contacts arbitrary addresses, it also guards against tricks that point it at internal systems.

**Why it matters:** Checking real behavior finds problems that reading plans cannot.

**New words:** **Ingress** — a Kubernetes rule that lets outside traffic reach a service · **Cloud Run** — Google's service for running apps without managing servers · **SSRF** — tricking a server into making requests to places it should not

## 5. Google and Meta let PyTorch run natively on Google's TPU chips
*InfoQ* · AI

**In one line:** TorchTPU lets people run PyTorch AI code on Google's TPU chips with only small code changes.

**What happened:** PyTorch is a popular tool for building AI models, and it mostly runs on Nvidia GPUs. Google's older way to run it on TPUs needed big code changes and was slow to compile. TorchTPU is a new open-source backend made with Meta. Moving from GPUs mostly means changing the device name from cuda to tpu. Google tested about 5,000 Hugging Face models this way. The project is still early, and the roadmap includes more operator coverage and compile speed.

**Why it matters:** More chip choices can make AI work cheaper and less tied to one vendor.

**New words:** **TPU** — Google's own chip built for AI · **PyTorch** — a popular toolkit for building AI models · **Eager execution** — running each step right away

## 6. Discord merged its video players and cut player code by up to 94%
*Discord Blog* · Frontend

**In one line:** Discord found four separate video players and built one shared player to replace them.

**What happened:** Discord's two biggest players shared no code and had no tests. So every feature and fix was done twice. The team did not rewrite from scratch. They wrote tests first, then split the old Quest player into pieces that both old and new players could share. The Clips team joined early, which pushed the shared design. A test on a million users showed key numbers within 0.1% of the old player. The new player also adds hover previews on the timeline and playback speeds.

**Why it matters:** Test first, then move step by step, and a big change can ship with nobody noticing.

**New words:** **Refactor** — reorganizing code without changing what it does · **Playwright** — a tool that tests apps by driving a real browser · **Spritesheet** — one image made of many small preview pictures

[Read the full post →](https://discord.com/blog/modernizing-the-video-playback-experience-at-discord)
