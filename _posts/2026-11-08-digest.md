## 1. An Android app with no code can trap a phone in a crash loop
*Bitdefender Labs* · Security

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-08/1.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-08/1.mp4"></video>

**In one line:** Researchers found that installing a specially built Android app can make the phone crash over and over, even if you never open it.

**What happened:** An Android app is really a ZIP file, and every file inside it says how it is stored and how big it is. Two parts of Android read those labels in slightly different ways. One part never checks the size for entries marked with an unusual storage type, and the other part trusts that size and asks the system for memory the file never had. When Android reads that empty space, the process is killed. If the broken file is one a core system service reads, the phone crashes, restarts, reads it again and crashes again. Restarting and safe mode do not help, and the researchers say a factory reset may be needed. Google called it outside the scope of a security fix. The researchers have not seen it used against real people.

**Why it matters:** An attacker could in theory lock someone's phone for extortion or make a bad app impossible to uninstall, and today the main defence is a scanner that spots the odd file before it is installed.

**New words:** **APK** — the file format of an Android app, which is a ZIP file · **Parser** — code that reads a file and understands its parts · **Crash loop** — a program that crashes, restarts and crashes again, forever · **Factory reset** — wiping a phone back to its original state

  B --> C[Check B maps too much memory]
  C --> D[System service reads empty space]
  D --> E[Crash, restart, repeat]
</pre>

## 2. Web frameworks trust a header that proxies never clean
*Lauri Koskela's blog* · Security

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-08/2.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-08/2.mp4"></video>

**In one line:** Many popular web frameworks believe a request header called `Forwarded`, but most proxies let a visitor's fake version through untouched.

**What happened:** When a proxy sits in front of a website, it adds headers that tell the site who the real visitor is. The newer `Forwarded` header does this job, but almost no proxy handles it, so a visitor can send their own. Rails, Spring and Jetty can read it by default and may trust it over the proxy's own header. That lets an attacker fake their IP address, the site name or whether the request was secure. These tricks can bypass IP limits, send password-reset links to the wrong site, or poison a cache. The author found signs of this on many bug-bounty sites. Rails and Spring have since changed their behaviour, and Spring Boot 4.2 now reads only `X-Forwarded-*` by default.

**Why it matters:** A "trusted proxy" setting does not help if the proxy passes the fake header along, so every layer must agree on which headers to trust.

**New words:** **Reverse proxy** — a server in front of your app that passes requests to it · **Header** — a labelled note attached to a web request · **Spoofing** — faking a value to look like someone else · **Cache poisoning** — tricking a cache into storing and serving a bad response

<pre class="mermaid">
flowchart LR
  A[Visitor adds fake Forwarded] --> B[Proxy passes it through]
  B --> C[App trusts Forwarded]
  C --> D[Fake IP or site name used]
</pre>

## 3. A new Postgres add-on searches vectors without the memory-hungry graph
*InfoQ* · Backend

**In one line:** Tiger Data released pg_vectorsearch, an early-stage PostgreSQL extension that finds similar items using less memory.

**What happened:** AI apps store "vectors" — lists of numbers that describe the meaning of text or images — and look for the closest ones. The popular pgvector HNSW index links every vector to its neighbours in a graph. The new PRISM index instead sorts similar vectors into groups and stores them compressed, then searches only the groups that matter. In the company's own test with 100 million vectors, PRISM built its index in 1 hour 40 minutes on a 128 GB machine, while HNSW took 42 hours on a 512 GB machine. It is alpha, needs PostgreSQL 18 or later, and does not yet support searches that also filter with WHERE. The benchmarks have not been independently confirmed.

**Why it matters:** If it holds up, teams could keep vector search inside the database they already use instead of running a separate one.

**New words:** **Vector** — a list of numbers that captures the meaning of something · **Extension** — an add-on that gives a database new abilities · **Index** — a shortcut structure that makes searching faster · **Alpha** — an early version not ready for real use

<pre class="mermaid">
flowchart LR
  A[Vectors] --> B[Group similar ones]
  B --> C[Compress each group]
  C --> D[Search only nearby groups]
</pre>

## 4. Grab protects its app from crashes as AI writes more code
*InfoQ* · Mobile

**In one line:** Grab added several safety layers so more AI-written code does not mean more app crashes.

**What happened:** AI coding tools mean more code changes land every week at Grab, so more chances for a crash. Grab catches problems early with code checkers (lint tools), tests, and an internal early-access app used by staff. Then it releases to a small share of users first and can pause if crashes rise. New features sit behind switches ("feature flags") that can be turned off without a new release. After release, live crash monitoring and automatic triage help link a crash to the exact change behind it. Lessons from each incident feed back into new checks and tests.

**Why it matters:** A crash that ships stays on people's phones for a long time, because not everyone updates quickly.

**New words:** **Feature flag** — an on/off switch for a feature that works without a new release · **Staged rollout** — sending an update to a few users first · **Lint** — a tool that scans code for likely mistakes · **Crash-free rate** — the share of sessions that finish without a crash

<pre class="mermaid">
flowchart LR
  A[Lint and tests] --> B[Staff early access]
  B --> C[Staged rollout]
  C --> D[Crash monitoring]
  D --> E[Turn off flag or pause]
</pre>

## 5. Edera wants AI agents to act without ever holding your keys
*InfoQ* · Security

**In one line:** Edera launched a security model that lets AI agents do approved jobs without having passwords or tokens inside them.

**What happened:** Today agents often run with secret keys placed right next to them, so a tricked agent can leak the keys. Edera's "Bounded Authority" keeps the permission to act separate from the secret itself. For example, a coding assistant could be allowed to change one GitHub repository without holding a personal access token. Tools called capcurl and capsudo send approved web requests and commands through a protected go-between, and workload identity is checked cryptographically. The rules are enforced at the hypervisor level, the layer under the operating system. Only the command and identity parts are out now; credential-brokered API access comes later.

**Why it matters:** If an agent is hijacked, the damage stays limited to the one job it was allowed to do.

**New words:** **Prompt injection** — hiding instructions in text so an AI follows them · **MCP server** — a connector that lets an AI use outside tools and data · **Hypervisor** — software that runs and separates virtual machines · **Blast radius** — how much can be harmed if something breaks

<pre class="mermaid">
flowchart LR
  A[Agent asks for action] --> B[Broker checks allowed task]
  B --> C[Broker uses the secret]
  C --> D[Action done, agent never sees key]
</pre>

## 6. One engineer replaced a pricey cloud DNS service with a script
*Vincent Bernat's blog* · Cloud

**In one line:** A blogger moved from Amazon's Route 53 to Bunny DNS and let a small script pick the nearest servers.

**What happened:** DNS is the internet's phone book, and "GeoDNS" gives each visitor the address of a nearby server. The author runs seven small servers around the world. Bunny DNS runs a bit of JavaScript for every query, so the script can return the two closest servers. A problem appeared: someone in Buenos Aires could get São Paulo and far-away Ashburn, and may use the far one. So the script returns only the closest server, with a short two-minute lifetime, when the second is much farther away. The newer HTTPS record could fix this but Chrome ignores some of its forms. The bill fell from US$5 to US$1 per month, though Bunny lacks HTTP/3 and DS records.

**Why it matters:** Programmable DNS lets small teams get fast, regional routing without paying for big cloud features.

**New words:** **DNS** — the system that turns website names into server addresses · **GeoDNS** — DNS that answers differently depending on where you are · **TTL** — how long an answer may be remembered before asking again · **CDN** — servers around the world that deliver content from nearby

<pre class="mermaid">
flowchart LR
  A[Visitor asks DNS] --> B[Script finds location]
  B --> C[Pick two closest servers]
  C --> D{Second far away?}
  D -->|Yes| E[Return one, short TTL]
  D -->|No| F[Return both]
</pre>
