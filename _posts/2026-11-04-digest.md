## 1. Netflix uses AI agents to hunt down slow code
*Netflix (via ByteByteGo)* · AI / Backend

**In one line:** Netflix built AI helpers that read performance data, find wasteful code, and suggest fixes that humans approve.

**What happened:** Finding slow code used to be manual work. An engineer had to study a "flame graph", which is a picture of where a program spends its time. Netflix now feeds this data to an AI model and tells it to look only at the company's own code. The agent found real problems. One regex (a text-matching pattern) used 46% of a service's CPU, and a swap to a lookup table made it 22 times faster. Another service spent 66% of its CPU just looking up a counter, while the real work used 0.3%. Every fix is tested, tried on a small "canary" copy of the live service, and then reviewed by a human. Netflix also keeps a shared list of known bad patterns in plain text files in Git, so the AI does not repeat work.

**Why it matters:** AI helps people write code faster, but that code can be slow. This shows AI can also clean up after itself, with humans still in charge.

**New words:** **Flame graph** — a picture showing which parts of a program use the most time · **Canary deployment** — trying a change on a small slice of real traffic first · **CPU** — the computer's main "thinking" chip

## 2. Meta lets each ad feature ship on its own
*Engineering at Meta* · Backend / AI

**In one line:** Meta changed its ad-ranking system so one broken piece no longer blocks all the others from launching.

**What happened:** Meta's ad models use more than 20,000 "features", which are small facts such as how many clicks an ad got in 7 days. They were all bundled into one big shared graph so common work only ran once. But that bundle shipped as one unit. If one feature had an error, none of them could go out. The new system, F3 Lightning, lets each feature ship alone. To avoid slowing things down, it finds shared work at startup, puts it in one order, and keeps results in one block of memory. The result is that new features reach production about 3.6 times faster with no extra computing cost.

**Why it matters:** It is like a cargo ship where one bad box used to hold back every box. Now each box can ship on its own, and models can improve faster.

**New words:** **Feature** — a piece of data a model uses to make a prediction · **Graph** — steps linked together, where one step needs the result of another · **Cache** — fast memory close to the CPU

## 3. LinkedIn follows one tap all the way to the database
*InfoQ* · Backend / Observability

**In one line:** LinkedIn links what a user does in the app to what happens inside its servers.

**What happened:** When you tap a button, many requests may fly across many services. LinkedIn uses OpenTelemetry, a common standard for recording these steps, in its phone, web and server code. It adds a "pageForestId" that groups all requests from one page, so engineers can see the whole experience. The data goes through Kafka and is stored in ClickHouse. Because recording everything is too much, it samples, and it makes sure the app and servers keep or drop the same journey together. It also filters out sensitive data.

**Why it matters:** Users feel a slow page, not a trace ID. Linking the two shortens the path from "this felt broken" to the cause.

**New words:** **Tracing** — recording the path of a request through many services · **Sampling** — keeping only some data to save space · **Kafka** — a pipe that moves large streams of data

## 4. Cloudflare launches a news feed for critical security bugs
*Cloudflare* · Security

**In one line:** Zero Wire gives security teams a short, plain-English card for each serious new vulnerability.

**What happened:** AI is helping people find software flaws faster, so teams get more alerts. Zero Wire, part of Cloudflare Radar, explains each serious bug in plain words. Each card says who should check, what to do now, and links to evidence like vendor advisories. It also offers a prompt you can give an AI agent to check your own systems in read-only mode. Cloudflare notes that a firewall rule is only a stopgap, and the real fix is updating the software.

**Why it matters:** Less time is spent gathering facts, and more time goes to fixing.

**New words:** **Vulnerability** — a weakness attackers can use · **CVE** — an official ID for a known vulnerability · **WAF** — a web firewall that blocks bad requests

[Read the full post →](https://blog.cloudflare.com/zero-wire/)

## 5. PostHog moves its data warehouse off DuckDB
*PostHog* · Backend / Data

**In one line:** A tool that was great on one machine hit limits when used as a cloud service at huge scale.

**What happened:** Five months ago PostHog rebuilt its warehouse on DuckDB, giving each customer their own instance. Customer queries grew bigger than expected, and a single machine had to be sized before each query ran. Its storage layer, DuckLake, held about 2 PB (around 1 trillion rows), and one write could take over three minutes. Supporting direct Postgres connections was also harder than expected. So PostHog is rebuilding on Trino with its own table format, HogLake.

**Why it matters:** A tool can be excellent in one setting and a poor fit in another.

**New words:** **Data warehouse** — a big store built for analyzing data · **Single-node** — running on just one machine · **Table format** — rules for how data files are organized

[Read the full post →](https://posthog.com/blog/moving-off-duckdb)

## 6. Vercel blocks known-bad npm packages during builds
*Vercel* · Security

**In one line:** Vercel now checks and stops builds that use dangerous package versions.

**What happened:** Vercel checks lockfiles, which list the exact package versions a project uses, against a blocklist of malicious or vulnerable versions. It checks before install, and blocks downloads during install. New rules reach builds within minutes. If a blocked package is found, the deployment fails and names the package. This applies to all plans automatically.

**Why it matters:** Malicious install scripts run on your build machine, so stopping them early protects your secrets.

**New words:** **npm** — a huge shop of JavaScript packages · **Lockfile** — a file that pins exact package versions · **Blocklist** — a list of things not allowed

[Read the full post →](https://vercel.com/changelog/blocking-malicious-npm-packages-before-and-during-installation)
