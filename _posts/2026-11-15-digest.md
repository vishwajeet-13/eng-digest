## 1. Thousands of apps built with AI left private data open to anyone
*Crissy Field GmbH (with Handelsblatt)* · Security

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-15/1.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-15/1.mp4"></video>

**In one line:** Security researchers found that many apps made on the AI tool Lovable let anyone read their users' private data without logging in.

**What happened:** Lovable turns plain-English descriptions into working web apps. Many of these apps store data in a database service called Supabase. Researchers looked at 159,041 Lovable projects, and 34,545 used Supabase. Of 24,664 sites that sent database records as soon as they loaded, about 30% (7,403) had tables holding email addresses. Think of a shop that locks the front door but leaves the stockroom open. Examples included 80,000 forum profiles with 200,000 chat messages, ticket and food-sale records, and more than 1,000 records with passport details. The researchers say the 30% is not a confirmed leak rate, because some emails may be public on purpose. They did not publish how to get the data.

**Why it matters:** Easy app builders do not remove the need to check who is allowed to see what, especially before real customer data goes in.

**New words:** **Supabase** — a hosted database service many apps use · **Access control** — rules about who may read or change which data · **Common Crawl** — a public archive of copies of web pages

## 2. Robot hackers powered by AI are now scanning the internet at huge scale
*Cloudflare Blog* · Security

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-15/2.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-15/2.mp4"></video>

**In one line:** Cloudflare says free AI hacking tools are spreading fast, and it explains how companies can defend themselves.

**What happened:** An open-source tool called ARTEX let many AI agents test a target for weak spots at the same time. Its creator took it down on October 8. After that, copies spread, and there are now over 12,000 related repositories. Cloudflare says daily requests from such tools are up 30 times since October 1, and it tracks more than 50 tool families. In one incident, attackers used a stolen, never-expiring key from an automated build pipeline to get in, then made many new Workers and tried to copy databases. Cloudflare's advice is the "Modern Security Model", explained like protecting a house: strong outer gates, a guard checking behavior, bot detection, no hidden back doors, checking every delivery, and a neighborhood watch.

**Why it matters:** Attacks now move at machine speed, so old keys and forgotten doors get found quickly.

**New words:** **Penetration testing** — trying to break into a system on purpose to find weak spots · **Lateral movement** — an attacker hopping from one system to the next · **WAF** — a filter that blocks bad web requests · **Zero Trust** — letting people in only after checking who they are, one room at a time

## 3. Google open-sources a tool that finds quiet mistakes in AI agents
*InfoQ (from Google's developer blog)* · AI

**In one line:** AQuA watches real conversations of an AI agent and finds repeated bad behavior that normal monitoring misses.

**What happened:** An AI agent can answer "successfully" and still ignore what the user asked. Normal server monitoring would not notice. AQuA runs beside the agent and reads its logs from up to 1,000 recent sessions. It goes through five stages: sampling, reviewing, grouping findings, verifying groups, and tracking issues. For the cause, it compares failures with a saved copy of the deployed code and points to file and line numbers. In a travel-app test, it found six verified issues, such as skipping seat checks and losing a vegan preference. After prompt changes and a replay, sessions passing all checks went from 5 to 13. AQuA does not apply fixes itself.

**Why it matters:** AI agents can fail silently, so someone has to read what they actually do.

**New words:** **Agent** — an AI that takes steps and uses tools on its own · **Telemetry** — logs and traces a system records about itself · **Root cause** — the real reason something went wrong

## 4. A free database that speaks MongoDB's language but runs on Postgres reaches 1.0
*InfoQ* · Backend

**In one line:** DocumentDB 1.0 is an open-source database that stores flexible documents and understands MongoDB requests, but uses PostgreSQL underneath.

**What happened:** Many apps store data as documents, like a folder of notes, instead of strict tables. MongoDB is the best-known tool for that. DocumentDB is an add-on for PostgreSQL plus a gateway that translates MongoDB-style requests into Postgres ones, so most MongoDB tools and drivers work unchanged. Version 1.0 supports Postgres 15 to 18 and includes a Kubernetes operator. It uses the MIT license, which allows commercial use without sharing your own code. The project is under the Linux Foundation. Some people dislike the name, which is close to Amazon DocumentDB. Early speed comparisons are mixed and not conclusive.

**Why it matters:** Teams get another way to keep MongoDB-style code while using the popular Postgres database.

**New words:** **Document database** — stores data as flexible records instead of rigid tables · **Wire protocol** — the language a database client speaks to a server · **MIT license** — a very permissive open-source license

[Read the full post →](https://www.infoq.com/news/2026/11/mongodb-compatible-documentdb/)

## 5. Google Cloud lets you pin the Compute Engine API to a dated version
*InfoQ* · Cloud

**In one line:** You can now ask for a frozen, date-named version of Google's server-rental API, so later improvements cannot break your scripts.

**What happened:** For years, everyone shared one version, /v1, so Google feared changing even small defaults. Now there are stable versions named by date, released every quarter, starting with 2026-09-01. Preview versions end in "-preview" and last one year. You pick a version with a header or a query setting. If you pick none, you still get /v1, which has no end date. The date versions show partial results when one zone fails, give clearer error messages, and can tighten old permission checks. Client libraries, gcloud and Terraform handle this for you.

**Why it matters:** Providers can fix old quirks without surprising everyone who automates their servers.

**New words:** **API** — a way for programs to talk to a service · **Pinning** — locking to one fixed version · **IAM** — the system that decides who may do what in a cloud account

## 6. Dropbox built a robot that checks its cookie choices on 200+ web pages
*InfoQ (about Dropbox Engineering)* · Frontend / Privacy

**In one line:** Dropbox uses an automatic browser test to confirm its websites respect what visitors choose about cookies.

**What happened:** Cookies are small files websites store about you. Laws like GDPR say sites must respect your choices. Dropbox has over 200 web surfaces, so checking by hand is hard. Its "cookie auditor" uses Playwright, a tool that drives a real browser. It runs three tests per page: a US visitor, an EU visitor, and a visitor sending a "Global Privacy Control" signal. Each starts with a fresh browser, declines optional cookies, reloads, and checks the choice stuck. It finds the buttons by their underlying elements, not their words, since Dropbox supports 22 languages. The approved cookie list lives outside the code so the privacy team can update it. A second tool finds every live page. A weekly report separates likely violations from known false alarms.

**Why it matters:** Privacy promises only count if something keeps checking them as pages change.

**New words:** **Cookie** — a small file a website saves in your browser · **GDPR** — Europe's data privacy law · **Playwright** — a tool that controls a browser automatically for tests

[Read the full post →](https://www.infoq.com/news/2026/11/dropbox-cookie-auditor/)
