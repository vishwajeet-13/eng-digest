## 1. A hidden bug in NGINX, the web's front door, lets strangers run code on servers
*Wiz Blog* · Security

**In one line:** Two serious flaws in NGINX, one of the most used web servers, let an attacker take over a server if HTTP/2 is turned on.

**What happened:** NGINX is like a doorman for websites. It receives visitors' requests and sends them to the right app. Researchers at Wiz and several other teams found two bugs in how NGINX handles HTTP/2, a modern way for browsers and servers to talk. One bug had hidden in the code since 2015. The other had been there for nearly six years. Both are rated 9.2 out of 10 for severity. An attacker does not need a password to use them. One was shown working on a server that only served plain static files. F5, the company behind NGINX, released fixes on 18 November.

**Why it matters:** The flaw is in NGINX itself, so a website can be exposed even if its own code is safe. Wiz says AI helped find these old bugs, and attackers can use the same tools. Update to NGINX 1.30.7 (stable) or 1.31.9 (mainline). If you can't update right away, turn HTTP/2 off.

**New words:** **Use-after-free** — a bug where a program keeps using memory it already gave back, so an attacker can sneak in their own data · **HTTP/2** — a newer version of the web's request language that lets many requests share one connection · **Remote code execution** — an attacker making your server run commands they choose · **CVE** — a public ID number for a known security flaw

## 2. Google releases Gemini 4 Neon, a fast "middle" AI model for coding and office work
*Google Blog* · AI

**In one line:** Google launched a new AI model that aims to be nearly as smart as its biggest ones but faster and cheaper.

**What happened:** Gemini 4 Neon sits in the middle of Google's Gemini 4 family. The bigger Carbon handles the hardest long projects. Hydrogen handles quick everyday jobs. Google says Neon scores 61 on the Artificial Analysis Intelligence Index, third overall, just behind larger and slower models. It costs $3 per million input tokens and $15 per million output tokens, and it can read 1 million tokens at once. Google says it costs 32% less per task than Carbon at its default setting. It is rolling out in the Gemini API, Google AI Studio, Google Antigravity and the Gemini app. A separate "for cyber" version is going to trusted security defenders.

**Why it matters:** Teams can now pick a model that balances brains and price. Remember that the scores in this post come from Google and its chosen benchmarks.

**New words:** **Token** — a small chunk of text, about a word or part of one, that AI models read and are billed by · **Context window** — how much text the model can keep in mind at once · **Benchmark** — a standard test used to compare AI models

[Read the full post →](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-neon/)

## 3. Meta uses AI agents to spread ML improvements across its ads models
*Engineering at Meta* · AI

**In one line:** Meta says AI agents now do over 60% of the work of moving proven improvements to its many ad-ranking models.

**What happened:** Meta runs a large number of models that decide which ads to show. When engineers find a better technique on one model, it almost never works on another by simple copy and paste. Each model needs its own tuning, which used to take expert engineers lots of time and many costly training runs. Meta built agents that find which techniques are worth trying, adapt them to each model, and run and watch the training jobs. They also fix failures and shift computing power to the most valuable jobs. Meta estimates this gives 3x more engineering output, a median 4x drop in training compute for some combinations, and over $45M in compute savings by the end of the year.

**Why it matters:** It shows AI agents doing real, judgment-heavy engineering work at huge scale. Engineers now mostly approve plans and set priorities.

**New words:** **Ranking model** — an ML model that sorts items, like ads, by how useful they will be · **Hyperparameter** — a setting you choose before training a model, like a dial · **Training run** — one full round of teaching a model with data

## 4. LinkedIn moves "shuffle" data off its compute machines and failures drop from 750 to 20 a day
*InfoQ* · Backend

**In one line:** LinkedIn gave the temporary data in its big data jobs a separate home, and jobs now fail far less.

**What happened:** Big data jobs split work across many machines, then must regroup the pieces in a step called a shuffle. LinkedIn used to keep this temporary data on the same machines that did the computing, so the two fought over CPU, memory, disk and network. It switched to Apache Celeborn, where dedicated workers store and merge this data. Daily fetch failures fell from about 750 to 20. Compute costs dropped 10% and job run times improved 14%. Moving storage to fast NVMe disks cut shuffle time by 40%.

**Why it matters:** Keeping two kinds of work apart stops them from slowing each other down, a pattern useful far beyond data engineering.

**New words:** **Shuffle** — moving intermediate data between steps of a big data job · **Apache Spark** — a tool for processing huge data sets across many machines · **NVMe SSD** — a very fast kind of disk

## 5. Google rewrites its famous SRE book for the cloud and AI era
*InfoQ* · Cloud

**In one line:** Ten years after the first edition, Google published a fully rewritten second edition of its book on keeping big systems reliable.

**What happened:** The original book showed how Google runs production services using software engineering. The new edition says the big challenge now is keeping systems reliable as they grow more connected and change all the time. It updates ideas like goals for reliability (SLOs), alerts that fire when you use up your allowed failures too fast, and tools like OpenTelemetry. It also covers automation, continuous testing of resilience, and planning for scarce GPU and TPU chips. On teams, it describes reliability experts sitting inside product teams, not only in a separate group. The authors say the culture of caring about reliability has not changed.

**Why it matters:** It is a free-to-follow roadmap of how a top engineering firm thinks about reliability today.

**New words:** **SRE** — site reliability engineering, using software skills to keep services running well · **SLO** — a target for how reliable a service should be, such as 99.9% working · **Error budget** — the amount of failure your SLO allows · **Observability** — being able to see what a system is doing from its logs, metrics and traces

## 6. PyPI tightens checks on uploaded Python packages
*PyPI Blog* · Security

**In one line:** PyPI now rejects some oddly built package files that could be read differently by different tools.

**What happened:** Python packages are shipped as archive files, either source tarballs or ZIP-based wheels. Tools that open these files are often forgiving about small oddities. An attacker could use that to make PyPI, a scanner and pip each see different contents in the same file. PyPI has begun to reject old "V7" style tar files and wheels with ZIP comments that could be misread as control data. For people who install packages, nothing changes. Maintainers who see an upload fail should build with a standard Python build backend.

**Why it matters:** It closes a sneaky way to make a malicious package look harmless to scanners.

**New words:** **Parser differential** — when two programs read the same file and understand it differently · **sdist** — a source distribution, the package as source code in a tar file · **Wheel** — a pre-built Python package, stored as a ZIP file
