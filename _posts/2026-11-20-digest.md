## 1. A tiny Ruby bug could let attackers take over Rails websites
*Veria Labs* · Security

**In one line:** A one-byte mistake in how Ruby capitalizes the letter "ß" can be used to attack many Ruby web apps.

**What happened:** Ruby has code that turns text into capital letters. In some older text encodings, "ß" has no capital form, so Ruby writes two letters, "SS", in its place. The code only checked for room for one letter. The output space is the input length plus 20 bytes, so an input with 21 of these characters spills one byte past the end. The bug has been in Ruby since version 2.4.0. Rails and classic-style Sinatra apps are affected by default. Veria Labs plans to publish a working remote-code-execution exploit on 25 November, or later if big vendors have not shipped fixes.

**Why it matters:** Fixed Ruby versions are 3.3.14, 3.4.13 and 4.0.10. GitLab and GitHub Enterprise Server had no fixed release yet when the post was updated.

**New words:** **Heap overflow** — writing data past the end of the memory set aside for it · **Encoding** — the rules for turning letters into bytes · **Remote code execution** — an attacker running their own commands on your server

## 2. How an AI-powered attacker broke into Railway in about a day
*The Pragmatic Engineer* · Security

**In one line:** The cloud company Railway shared a detailed story of how an attacker with an unrestricted AI model stole customers' AI keys.

**What happened:** The attacker first tried and failed to get in using dummy accounts. Then they found a way to read files on Railway's build system and stole build credentials. That led to Railway's source code. Within hours the attacker planned the next steps and got cloud access through a misconfigured deploy pipeline setting. From there they used a key service to decrypt customers' AI provider keys. Railway's team was only minutes behind at one point. The attacker came back the same night after being kicked out.

**Why it matters:** Once attackers have your code, an AI can find weak spots in hours instead of days. Railway now gives each build its own throwaway virtual machine and uses tighter access rules.

**New words:** **Credential** — a secret, like a key or password, that proves who you are · **Hash** — a scrambled fingerprint of a secret that cannot be turned back · **Build system** — the machines that turn code into a running app

## 3. PostgreSQL 19 makes cleanup and slow queries easier to handle
*PostgreSQL project* · Backend

**In one line:** The popular free database got a new release with tools that fix problems without taking tables offline.

**What happened:** Tables with many updates and deletes build up wasted space called bloat. The new REPACK (CONCURRENTLY) command cleans it up without blocking reads or writes. A new extension, pg_plan_advice, lets you keep a query on a good plan when the database might pick a slower one. A new "get or create" option for inserts saves a trip to the database. Bulk inserts got nearly 2x faster in testing thanks to quicker foreign key checks. JIT compilation is now off by default.

**Why it matters:** Postgres runs a huge number of apps. Less downtime for maintenance is a real win.

**New words:** **Bloat** — unused space left in a table by old data · **Query plan** — the database's step-by-step method for answering a question · **Replica (standby)** — a copy of the database that serves reads

## 4. Yelp moved 90 databases to a new Kubernetes setup by moving the disks
*InfoQ* · Cloud

**In one line:** Yelp moved its Cassandra databases by re-attaching their existing disks instead of copying the data.

**What happened:** Copying data between clusters can take weeks for the biggest ones. Yelp noticed that an EBS disk belongs to an availability zone, not to a Kubernetes cluster. So it pointed new pods in the new cluster at the same disks. One pod at a time, the old pod was deleted, the disk detached, and the new pod picked it up with the same data. About 90 clusters moved this way with zero downtime and no data loss. Rolling back was the same steps in reverse.

**Why it matters:** The trick avoids double compute cost and long data transfers for any stateful app tied to a disk.

**New words:** **Cassandra** — a database that spreads data across many machines · **EBS volume** — a virtual hard disk in Amazon's cloud · **StatefulSet** — a Kubernetes way to run apps that must keep their data

## 5. Discord is rewriting its apps in Rust to make them lighter and faster
*InfoQ* · Frontend

**In one line:** Discord plans to drop Electron and React Native for a Rust core with a GPU-drawn desktop app.

**What happened:** Discord's CTO said the project, called Phoenix, removes Electron on desktop. The desktop app uses GPUI, the interface framework from the Zed editor. Mobile keeps native screens but shares a Rust core with desktop. Early internal builds use about 290 MB of RAM with two accounts, and start almost instantly versus 5.5 seconds on Electron. Mobile loads in under 2 seconds versus about 5 seconds. The trade-off is giving up browser features like text layout and screen-reader support, which must be rebuilt.

**Why it matters:** It shows a big app betting that speed is worth the cost of building more itself.

**New words:** **Electron** — a tool that wraps a website in a desktop app · **GPU** — the chip that draws graphics · **Rust** — a fast programming language focused on safe memory

## 6. Zerodha built a blob store on SQLite
*Zerodha Tech* · Backend

**In one line:** Zerodha stores users' saved chart layouts in a small Rust server built on SQLite.

**What happened:** Their trading platform Kite has about 20 million customers who save layouts and settings as JSON blobs up to several megabytes. The old store, SSDB, became unmaintained and ran on only one node. Zerodha tried many databases and found none a good fit. So they built Blobasaur, which speaks the Redis protocol and splits data across SQLite shards. In production on three small servers, p99 latency stays around 2 ms. Background cleanup of expired data caused spikes until it was made to share the writer and work in chunks of 1,000 rows.

**Why it matters:** Sometimes a simple tool, SQLite, is enough when you know exactly what you need.

**New words:** **Blob** — a chunk of data stored as-is · **Shard** — one slice of a split-up database · **p99 latency** — the time within which 99 of 100 requests finish
