## 1. A July software change knocked out Microsoft email for a day
*The Register* · Cloud / Outages

**In one line:** Microsoft says a small bug added in July lay hidden for months, then took down most of its network gateway servers and stopped Exchange Online email.

**What happened:** Microsoft's early report says a code change shipped in July passed its load tests. The tests mostly used weaker machines with fewer cores, so they missed a flaw: on bigger, newer machines, processes fought over the same lock and used up all the CPU and memory. On 12 November, Teams traffic moved to the main gateway at the same time as about 14% of gateway capacity was out of service. Together these pushed the bug into action. Think of a busy shop where one cashier falls over, so customers go to the next one, who also falls over. Within two hours, more than 80% of servers stopped responding. Restarting servers did not help, because they were swamped again at once. Engineers could not roll back, since the change was months old, so they wrote a patch that put the code back to its earlier good state and rolled it out group by group.

**Why it matters:** It shows how a hidden bug plus a traffic spike can spread across a whole system. It also shows why tests must look like real hardware and real load. A final report is due 20 November.

**New words:** **Load testing** — pushing a system with lots of fake traffic to see if it copes · **Lock contention** — many programs waiting for the same shared resource, so everything slows · **Cascading failure** — one failure sends extra load to the next machine, which then fails too · **Rollback** — undoing a change to return to the old version

## 2. A password bug lets attackers walk into some Linux servers
*InfoQ* · Security

**In one line:** A flaw called "sshole" lets someone log in to accounts with no password by typing a very long fake password, and attackers are already using it.

**What happened:** Linux marks an account that has no password with an asterisk (`*`) in a file. On servers using the musl library (like Alpine Linux) without PAM, a password longer than 256 bytes makes musl's `crypt()` function return an error — and that error is also an asterisk. OpenSSH sees the matching asterisk and thinks the password is right. Two changes made in 2012 in musl and a timing-attack fix in OpenSSH from 2016 combined to create this. On Alpine's official AWS and Azure images, the default user can use `doas` without a password, so the attacker gets root. A group tracked as GT10 is reported to be exploiting it.

**Why it matters:** Small, harmless-looking choices made years apart can add up to a serious hole. If you run Alpine or other musl-based systems, update.

**New words:** **musl** — a small C library used by Alpine Linux · **PAM** — a common Linux login-checking layer · **CVE** — a public ID number for a security flaw · **Shadow file** — the file where Linux stores password hashes

**Fix:** Upgrade to OpenSSH 10.6p2, or set `PasswordAuthentication no` and restart `sshd`. Red Hat and Amazon Linux 2/2023 are not affected.

## 3. AWS lets each Kubernetes pod run in its own mini virtual machine
*InfoQ* · Cloud

**In one line:** AWS Nitro Sandboxes give a pod its own tiny virtual machine with one extra line of config.

**What happened:** Normally, containers on a server share one operating-system core (kernel), so a bad container could affect its neighbours. AWS now starts a lightweight Firecracker virtual machine for each opted-in pod, with its own kernel. On Amazon EKS you add `runtimeClassName: isolated-sandbox` or `confidential-sandbox` to the pod. Confidential mode also treats the host machine as untrusted and checks the pod's image and policy. It is free and available in all commercial regions. AWS names coding agents first as a use. The limits: no GPU support yet, and a cap on how many sandboxes fit on a node.

**Why it matters:** Running untrusted code, such as AI coding agents, gets safer without redesigning your apps.

**New words:** **MicroVM** — a very small, fast-starting virtual machine · **Kernel** — the core part of an operating system · **Pod** — the smallest unit Kubernetes runs, holding one or more containers · **Attestation** — proof that software is what it claims to be

## 4. Kubernetes will remove an old network mode, IPVS
*Kubernetes Blog* · Cloud / Backend

**In one line:** The Kubernetes team plans to remove kube-proxy's `ipvs` mode in version 1.40 and asks users to move to `nftables`.

**What happened:** `kube-proxy` is the part that sends traffic to the right service inside a cluster. The `ipvs` mode was built because the older `iptables` mode got slow in big clusters. But IPVS never matched every Kubernetes feature, its original authors moved on, and it still needs iptables for some jobs. It also lacks batch updates, so it can be slower on large changes. The newer `nftables` mode has been generally available since 1.33 and is about as fast. It is deprecated since 1.35. Switching means changing `mode: ipvs` to `mode: nftables` in the kube-proxy config and restarting it.

**Why it matters:** If you run clusters with IPVS, plan a migration before 1.40.

**New words:** **kube-proxy** — the Kubernetes component that routes traffic to services · **Deprecated** — still works but marked for removal · **Backend** — the engine doing the work behind a feature · **nftables** — the newer Linux packet-filtering system

## 5. How Instacart uses AI to understand what shoppers mean
*ByteByteGo* · AI / Backend

**In one line:** Instacart uses big language models offline to teach a small, fast model to understand messy searches like "bread no gluten."

**What happened:** Shoppers rarely type the exact product name. Instacart's older systems learned from clicks, which are noisy and thin for rare searches. Now an LLM picks categories from candidates, writes rewrites (synonym, broader, substitute) and pulls out tags like brand and flavor. A large "teacher" pipeline makes good examples ahead of time and saves answers for common searches. A smaller Llama-3 8B "student" model, tuned with LoRA, handles new ones live. Merging the LoRA weights and moving to H100 GPUs brought latency to about 300 ms. Only about 2% of queries need live model work. Instacart reported 50% fewer complaints about poor search results for rare queries.

**Why it matters:** A cheap model, a cache and a strong offline teacher can bring LLM quality to a busy site without huge cost.

**New words:** **Query understanding** — working out what a shopper really wants · **RAG** — giving the model helpful facts in the prompt · **Fine-tuning** — extra training on your own examples · **Distillation** — a small model learning from a bigger one's answers · **Cache** — saved answers for fast reuse

## 6. Hugging Face now routes open-model requests through OpenRouter
*Hugging Face Blog* · AI

**In one line:** One Hugging Face token can now call open-weight models, with OpenRouter picking the best provider each time.

**What happened:** Hugging Face is switching its Inference Providers service from its own router to OpenRouter's. The router picks a provider based on live price, speed and reliability, and retries on another one if a call fails. It supports OpenAI's Chat Completions and Responses APIs and Anthropic's Messages API. The post says open-weight models rose from 26.8% of tokens served on OpenRouter in October 2025 to 71.7% at the end of September 2026.

**Why it matters:** Trying many open models gets easier, with no code changes.

**New words:** **Open-weight model** — an AI model whose trained numbers are public so anyone can run it · **Router** — software that picks where each request goes · **Inference** — running a trained model to get an answer · **API** — a way for programs to talk to each other
