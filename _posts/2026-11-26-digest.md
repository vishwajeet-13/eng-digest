## 1. 1Password says hackers copied customer names and emails, but not vault data
*1Password* · Security

**In one line:** An attacker got into 1Password's back-end systems through a stolen employee GitHub login and copied some customer account details.

**What happened:** On 19 November 2026, 1Password began checking signs that someone had taken over an employee's work GitHub account. The attacker used it to read source code and push bad code to back-end services. That code downloaded account records for some customers: names, email addresses, sign-in times and some internal IDs. It also grabbed tokens that sit in emailed invite and account-recovery links. 1Password says vault contents and the keys protecting them were never reached, because it does not hold those keys. It turned off the account, rotated its internal secrets and made recovery codes longer, from 6 digits to 10 letters and numbers.

**Why it matters:** Even a company built around secrets can be hit through one employee login, so watch for fake "1Password" emails asking you to click an invite or recover an account.

**New words:** **GitHub account** — the login where a team stores and edits its code · **CI/CD** — the automatic machinery that builds and ships code · **Token** — a secret string that proves who you are · **Phishing** — a fake message that tricks you into giving up secrets

## 2. A crafted web request let an attacker run commands on the Elixir/Erlang package site Hex.pm
*Hex.pm* · Security

**In one line:** Hex.pm, where Elixir and Erlang programmers download code libraries, was hacked on 23 November and everyone had to be logged out.

**What happened:** Someone sent 69 harmful requests to hex.pm in 13 minutes. The site unpacked a special data format sent by anyone, even strangers. Attackers can hide a fake "object" in that data. When the site tried to print an error about the odd request, the printing step ran code the attacker had chosen, and that led to running commands on the servers. Hex.pm blocked the traffic and shipped a fix in about 20 minutes. Its team found no sign of changed packages, but cannot rule out that data like email addresses and password hashes were read. They replaced all server secrets and are building a new signing system.

**Why it matters:** Code libraries are trusted by thousands of projects, so a break-in at the library store is a break-in risk for everyone downstream. If you use Hex, change your password and reset 2FA.

**New words:** **Package registry** — a public store where programmers download ready-made code · **Remote command execution** — an attacker running their own commands on your computer · **Password hash** — a scrambled form of a password · **2FA** — a second proof of identity, like a code from an app

## 3. Researchers took over five US Treasury web addresses for about $3 each
*Intruder* · Security

**In one line:** Forgotten website records pointing at rented cloud addresses can be claimed by anyone who gets that address.

**What happened:** Websites use DNS records, like phone-book entries, to point a name to a numbered address. AWS lets anyone rent public addresses, called Elastic IPs. If a company drops an address but forgets the record, the name still points there. The researchers rented and released addresses over and over and checked each against a list of names. In 48 hours they went through 450,000 addresses and took over 28 live ones, including five treasury.gov subdomains. AWS then banned their account, but they moved the addresses to a new account in the same organization. AWS told them it has no plans to change anything.

**Why it matters:** An attacker holding a real .gov name can run convincing phishing pages. Delete DNS records the moment you stop using the address.

**New words:** **DNS** — the internet's phone book that turns names into addresses · **Elastic IP** — a public internet address you rent from AWS · **Dangling record** — a DNS entry that points to something you no longer own · **Subdomain** — a name in front of a main site, like `ftp.` in `ftp.example.gov`

## 4. AWS Lambda lets a single run last 30 minutes, double the old limit
*InfoQ* · Cloud

**In one line:** AWS raised the longest time one Lambda function can run from 15 to 30 minutes.

**What happened:** Lambda runs small pieces of code without you managing servers. When it launched in 2014 a run could last 60 seconds; it became 5 minutes in 2015 and 15 minutes in 2018. Now it is 30 minutes in all regions at normal pricing. AWS points to chained AI tool calls, video conversion, simulations and report building as jobs that outgrew 15 minutes. The article warns that longer runs need more simultaneous capacity: 1 request per second at 30 minutes each needs 1,800 runs going at once. Some people say slow code behind a website is still the wrong use.

**Why it matters:** Longer jobs fit in Lambda, but check cost and queue settings before moving them.

**New words:** **Lambda** — AWS's service that runs your code only when needed · **Timeout** — the longest time code may run before being stopped · **Concurrency** — how many copies of your code run at the same moment · **Dead-letter queue** — a holding box for jobs that keep failing

## 5. GitHub dropped CSS-in-JS and made its pages render 55% faster
*InfoQ* · Frontend

**In one line:** GitHub moved its styling out of JavaScript into plain style files and cut server rendering time by 55%.

**What happened:** Styles on many sites are written inside JavaScript, which makes the computer work out the styling every time a page is built. As GitHub's pages got more components, this got slow. Over three years, GitHub rebuilt its Primer design system on CSS Modules, which become ordinary style files shipped with the page. The team moved each component behind a feature flag and checked screenshots to be sure nothing changed. About 7,760 style spots had to be rewritten; the last 895 took two engineers three weeks using Copilot coding agents. Some readers doubted the user benefit.

**Why it matters:** Do the styling work once at build time, not on every request.

**New words:** **CSS-in-JS** — writing styling rules inside JavaScript code · **CSS Modules** — style files whose names are kept private to one component · **Server-side rendering** — building the page on the server before sending it · **Design system** — a shared kit of buttons and parts

## 6. Rust 1.100 finally ships the "never" type after ten years
*InfoQ* · Backend

**In one line:** The Rust language added `!`, a type that says "this never produces a value", after five failed tries.

**What happened:** Some code never finishes normally, like a crash or an endless loop. Rust used `!` for this only in limited places. Now you can name it anywhere, for example to say a task cannot fail. The release also makes a custom memory manager feature stable and adds a Cargo setting that waits a few days before using brand-new library versions. That waiting guards against fresh malicious releases, though critics say it must not delay urgent security fixes. Upgrade with `rustup update stable`.

**Why it matters:** Rust gets more precise at describing code, and Cargo gets a small shield against poisoned libraries.

**New words:** **Type** — a label saying what kind of data something is · **Cargo** — Rust's tool for building code and fetching libraries · **Allocator** — code that hands out computer memory · **Stabilise** — mark a feature as safe to rely on

## 7. Google DeepMind's Gemini Robotics 2.5 makes robots handier and safer
*InfoQ* · AI

**In one line:** A new robot "brain" does fiddly jobs like tying bows and pipetting, and comes with a safety test.

**What happened:** Gemini Robotics 2.5 is a model that sees, reads instructions and moves a robot's arms. DeepMind tested more than 200 tasks and reports 30% to 100% better success rates. In a Mercedes-Benz trial, humanoid robots reached a 96% success rate sorting metal brackets. Safety guidance raised safe task completion by 33% around obstacles and 43% around nearby people. DeepMind also released ASIMOV-jailbreak, a public set of unsafe prompts. One commenter noted that 96% is not enough around people.

**Why it matters:** When a trick prompt can cause a physical action, safety tests matter more than for chatbots.

**New words:** **Vision-language-action model** — an AI that looks, reads and then moves · **Dexterity** — skill at careful hand movements · **Benchmark** — a standard test to compare systems · **Jailbreak** — a prompt meant to make an AI break its rules
