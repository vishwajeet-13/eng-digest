## 1. DoorDash rebuilt its delivery matching system to handle 10x more orders
*InfoQ (from the DoorDash engineering blog)* · Backend

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-28/1.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-28/1.mp4"></video>

**In one line:** DoorDash split its "who delivers what" engine into a coordinator and many helpers, and it now handles ten times more work.

**What happened:** DoorDash has a system called dispatch. It decides which driver picks up which order. The old version was one big program that did everything. As orders grew, the math got too slow, and at peak times demand was about four times what the system could handle. So it sometimes used shortcuts and decided with incomplete information. The new version has two parts. A "coordinator" keeps track of the whole picture. Many "workers" do the heavy math on small slices of the map. Think of a head chef handing separate orders to many line cooks. DoorDash tested the new system quietly beside the old one first. Then it switched over step by step.

**Why it matters:** It shows a common way to scale a busy system: keep the memory in one place and spread the hard thinking across many helpers.

**New words:** **Dispatch** — the system that matches orders to drivers · **Stateless worker** — a helper that remembers nothing between jobs, so you can add more of them easily · **Shadow testing** — running a new system on real requests without using its answers yet

## 2. Hackers hid a card-stealing script inside video-call technology on five online stores
*InfoHawk News* · Security

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-28/2.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-28/2.mp4"></video>

**In one line:** A hidden script copied card details at checkout on five shopping sites and sent them out through a channel most security tools do not watch.

**What happened:** Researchers found a card-skimming script on the stores of Lascana, Samsonite, American Tourister, Revolve and FWRD in the week before Black Friday. It got in through a marketing tracker, a cookie-banner setting, or a file on a store's own network. The script used WebRTC, the browser feature behind video calls, to download itself and to send stolen data out. Security rules often miss that channel. It only ran on phone-sized screens at checkout, so desktop checks would not see it. The researchers saw it send a test card's details from Lascana. All five stores removed it on 24 or 25 November. It is not known how many shoppers were affected.

**Why it matters:** One tampered third-party script on a payment page can steal card details without anything looking wrong. If you shopped on these sites recently, check your statements.

**New words:** **Skimmer** — code that secretly copies payment details as you type them · **WebRTC** — a browser feature for live video, audio and data between two parties · **Tracking pixel** — a small third-party script a store loads to measure ads · **connect-src** — a site rule listing which hosts its pages may contact

## 3. Netflix built Quasar to see who uses a code library before changing it
*InfoQ (from the Netflix tech blog)* · Backend

**In one line:** Quasar tells Netflix engineers exactly which projects would break if they change or remove part of a shared code library.

**What happened:** Companies share code libraries across many projects. Changing one function can break things somewhere far away. Tools can say a change is incompatible, but not who actually uses that function. Quasar fills that gap. While projects are built, it records where each function is defined and used, and stores this index in Amazon's cloud storage. When someone proposes a change, Quasar compares the old and new versions and looks up who is affected. In one Netflix example, removing an old method touched 137 projects. It can miss hidden uses, such as code that finds functions at run time, so it does not prove something is safe to delete.

**Why it matters:** Knowing who depends on your code makes big changes less scary.

**New words:** **API** — the set of functions a library offers to other code · **Index** — a lookup table built ahead of time so searches are fast · **Reflection** — code that finds and calls functions while running, which static tools can miss

## 4. PyTorch lets an AI reviewer approve code from its own maintainers
*InfoQ* · Engineering practice

**In one line:** A new tool called GreenLight lets an AI approve small, low-risk code changes from trusted PyTorch maintainers.

**What happened:** At Meta, code written per developer is growing fast, partly because of AI tools, and human review is falling behind. Meta built RADAR to approve only low-risk changes automatically. PyTorch made an open-source version, GreenLight. It works only for authors named in PyTorch's merge rules. Others are reviewed in "shadow mode", and those reviews never count as approvals. Each change gets a risk score and an AI review, and a human can still reject it during a waiting period. The article says OpenAI, Anthropic and Sonar describe similar ideas: trust depends on who wrote the change and what it could break.

**Why it matters:** Teams are testing how much code review can safely be automated.

**New words:** **Pull request** — a proposed code change waiting for approval · **Codemod** — a script that makes the same edit across lots of code · **Shadow mode** — running a check without letting it affect real results

## 5. Firefox adds Mistral's open AI model to its Smart Window assistant
*InfoQ* · AI

**In one line:** Mozilla is bringing a French company's open AI model into Firefox, instead of tying the browser to one big AI provider.

**What happened:** Mozilla announced a partnership with Paris-based Mistral AI. Mistral Small 4 becomes a recommended model in Smart Window, Firefox's optional AI assistant, which is in beta. It starts in France, the US and Canada, with the UK and Germany planned. Users can pick from several models, such as Gemini, Qwen and Mistral. Conversations are not stored on Mozilla's servers by default, and Mistral agreed to keep no data. The model is "open-weight", so anyone can download it. Early feedback is mixed: some testers like the privacy controls, others do not want AI in a browser at all.

**Why it matters:** It is a different approach from browsers that lock users to one AI vendor.

**New words:** **Open-weight model** — an AI model whose trained settings are public to download · **Zero data retention** — the provider keeps none of your data after answering

## 6. OpenAI says its GPT-6 models can design new proteins, and early lab tests back it up
*OpenAI* · AI

**In one line:** OpenAI reports that a general AI model can design the shapes of new proteins by reasoning and writing code, and some of them stuck to their targets in a lab.

**What happened:** Proteins are tiny machines made of chains of building blocks called amino acids. A chain's order decides its 3D shape, and the shape decides what it does. Designing a protein usually needs several specialized AI tools. OpenAI says its GPT-6 models can design shapes alone, using only reasoning and general code. With a lab partner called Onava, it made 322 small proteins aimed at five targets. 35 of them (10.9%) showed binding. Specialized tools still picked the building-block order and chose which ones to test. OpenAI notes that predicting a full protein structure is still a clear weakness. It also says the same ability could be misused.

**Why it matters:** One general model might one day replace a toolbox of specialist tools in science.

**New words:** **Protein** — a molecule that does jobs inside living cells · **Minibinder** — a small protein designed to stick to a chosen target · **Binding** — a molecule attaching to its target
