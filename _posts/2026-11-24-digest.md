## 1. Cloudflare now tests its internet "phone book" from every data center, all day
*Cloudflare Blog* · Cloud / Backend

**In one line:** Cloudflare built constant fake-customer checks for DNS, so a bad release gets stopped before it spreads.

**What happened:** DNS is the internet's phone book. It turns a name like `example.com` into a machine address. Cloudflare once shipped a bug that left some record changes unpublished for hours. The service looked healthy, so nobody noticed. To catch this kind of problem, the team added DNS checks to Flamingo, an in-house testing tool that already runs hundreds of millions of tests a day. A test keeps changing a small record with a timestamp. It then asks Cloudflare's name servers and the public 1.1.1.1 resolver from every data center, and checks the answer is fresh enough (90 seconds and 600 seconds). If the numbers get worse in a test data center, the rollout can stop or roll back by itself.

**Why it matters:** Unit tests are not enough for big networks. Testing the way customers really see the system catches slow, partial failures.

**New words:** **DNS** — the system that turns names into addresses · **SLO** — a target for how well a service should work · **Error budget** — how much failure you can allow before you must act · **Canary** — a small first group that gets a change before everyone

## 2. DoorDash split its delivery matching into a boss and many workers, and got 10x the capacity
*ByteByteGo* · Backend / Architecture

**In one line:** DoorDash rebuilt the system that picks which driver gets which order so it can do far more work, much faster.

**What happened:** The system must decide which driver ("Dasher") takes which order. It has to think about time too. A close Dasher is a bad pick if the food takes 15 more minutes. The old engine was one big program, and its work grew roughly four times when the input doubled. At peak, demand reached nearly four times what it could handle. The new design has a "coordinator" that keeps the current picture and a group of "compute workers" that do the heavy math. The coordinator cuts the map into local clusters and sends each worker only the data it needs. A final step combines the local answers. DoorDash tested it first in "shadow mode", where the new engine made decisions that were only recorded, then in real experiments.

**Why it matters:** Adding more servers doesn't help if the work can't be split sensibly. Splitting the problem is the hard part.

**New words:** **Monolith** — one big program that does everything · **Sharding** — cutting data into smaller pieces · **Shadow testing** — running a new system on real traffic without using its results · **Stateless** — keeping no memory between jobs

## 3. Netflix taught its code base to talk to AI agents, and developer happiness went from -3 to +25
*InfoQ* · AI / Engineering practice

**In one line:** Netflix's Commerce team found that AI coding tools worked well only after the team fixed its docs and habits.

**What happened:** At first, an AI agent needed four tries just to migrate some tests. The docs were hard to find and the tests were written in different styles. The team then wrote 45 "architecture decision records", short notes written for both people and agents. An `AGENTS.md` file points agents to them, a bit like `robots.txt` for search engines. A review agent now checks pull requests and posts only verified problems. Engineers still own and merge the code. The talk reported no top-severity incidents in 2026 on a core service, 32% more pull requests, and a developer score that rose from -3 to +25.

**Why it matters:** AI speeds up teams that already have clear docs and consistent code. It doesn't replace them.

**New words:** **Agent** — an AI that can take steps on its own · **Architecture decision record** — a short note saying why a design choice was made · **Pull request** — a proposed code change for review · **Context engineering** — giving the AI the right information to work with

## 4. A second AI lab ships a model that "thinks" by looping its own layers
*Simon Willison's Weblog* · AI

**In one line:** Z.ai's new GLM-5.4 reuses the same layers several times in a row, instead of adding more layers.

**What happened:** An AI model is a stack of layers. Normally the data passes through each layer once. In a "looped transformer", a group of layers is run again and again, and each pass refines the last one. This gives a deeper network without more parameters, the numbers the model learns. Z.ai says GLM-5.4 is its first model built this way. Simon Willison notes it's the second such model in a week, after Inkling 2 Mini. GLM-5.4 isn't available as open weights yet. He had to use a paid coding plan to try it.

**Why it matters:** Looping is a possible way to make models smarter without making them much bigger.

**New words:** **Transformer** — the common design behind modern AI models · **Parameters** — the learned numbers inside a model · **Open weights** — a model whose files anyone can download

## 5. Five new nginx security holes: patch now, and a proxy can shield you meanwhile
*Cloudflare Blog* · Security

**In one line:** Researchers found five serious bugs in nginx, the web server software behind a huge share of the internet.

**What happened:** On November 18, nginx's makers disclosed ten flaws. Five of them, named "nginx2root", can crash a server or let an attacker run commands on it. The worst one only needs HTTP/2 switched on, and affects releases back to 2015. A related Linux kernel bug could then give an attacker full control of the machine, even from inside a Docker container. Cloudflare says its own edge is not affected. Servers behind its proxy are shielded from the HTTP/2 and HTTP/3 attacks, because the attacker's messages stop at Cloudflare. Cloudflare still tells everyone to update to nginx 1.30.7 or 1.31.9. It had seen no reports of attacks in the wild.

**Why it matters:** If you run nginx, update it. A shield in front is a stopgap, not a fix.

**New words:** **Reverse proxy** — a server that sits in front of another server and passes requests along · **Use-after-free** — a bug where a program uses memory it already gave back · **CVE** — a public ID number for a security flaw

## 6. Ladybird, a brand-new web browser built from scratch, reaches alpha
*Ladybird* · Frontend / Open source

**In one line:** You can now download an early version of a browser that doesn't use anyone else's engine.

**What happened:** Most browsers share a few engines under the hood. Ladybird has its own, built from the ground up and not copied from another. The team says it's now an alpha for macOS and Linux. Some sites won't work, and it will sometimes crash. You can report a broken site or a crash from inside it. It updates itself often. It supports WebDriver and the Firefox DevTools protocol, so site builders can test with it. The team makes no security promises yet and invites hackers to try to break it.

**Why it matters:** A new, independent engine means less dependence on the few big browser makers.

**New words:** **Browser engine** — the part that draws web pages · **Alpha** — an early test version · **WebDriver** — a standard way for programs to control a browser for testing

[Read the full post →](https://ladybird.org/posts/alpha/)

## 7. Kubernetes 1.38 preview: what's going away and what's becoming stable
*Kubernetes Blog* · Cloud / DevOps

**In one line:** The next Kubernetes release will drop some old settings and make a few features stable.

**What happened:** Kubernetes runs apps across many machines. The team posted a heads-up on version 1.38. Two old kubectl environment variables for turning off WebSockets will be removed. Support for the old "cgroup v1" system is still on its way out, so users should move to v2. In 1.38, the node agent will ask the container runtime which cgroup driver to use, so the runtime must be running first. Features expected to become stable include kuberc, a file for personal kubectl preferences, and pod-level resource limits. A new alpha EvictionRequest API will give apps time to finish work before a Pod is removed. The post notes these plans may change.

**Why it matters:** Teams running Kubernetes should check their scripts and nodes before upgrading.

**New words:** **Pod** — the smallest group of containers Kubernetes runs together · **kubectl** — the command-line tool for Kubernetes · **cgroup** — a Linux feature that limits what a process can use · **Alpha** — an early feature that may change

[Read the full post →](https://kubernetes.io/blog/2026/11/23/kubernetes-v1-38-sneak-peek/)
