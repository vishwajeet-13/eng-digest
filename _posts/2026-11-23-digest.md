## 1. Researchers planted 2 million fake secrets and found AI middlemen leaking them
*Ars Technica* · Security / AI

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-23/1.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-23/1.mp4"></video>

**In one line:** A test showed that cheap AI "router" services let some prompts, and the secrets inside them, get stolen or read.

**What happened:** Many AI apps don't talk to one AI company directly. They go through "AI routers" that pick the cheapest or best model for each request. Researcher HD Moore sent nearly two million prompts, each holding a unique fake secret, such as an AWS key or a private link. He then watched to see who used them. At least three hosting providers were broken into by attackers, who copied requests and used the fake keys tens of thousands of times. Some resellers logged prompts and passed them on. One Chinese AI lab fetched secret links from more than half the prompts sent to its models, even ones marked "Zero Data Retention". OpenRouter later told customers some prompts may have been read and removed a "Zero Data Retention" label from some endpoints.

**Why it matters:** A privacy label on a request doesn't guarantee privacy. Never put passwords or keys into a prompt, and prefer big providers you have a direct contract with.

**New words:** **AI router** — a middleman service that sends your prompt to a model it picks · **Canary** — a fake secret planted so you can tell when someone uses it · **Zero Data Retention** — a promise that your prompt won't be stored

## 2. Claude Code's "don't ask again" button has been saving passwords in public repos
*InfoQ* · Security / AI

**In one line:** An AI coding tool stored approved commands, passwords included, in a file that often ended up on GitHub.

**What happened:** When you tell Claude Code "Yes, and don't ask again", it saves that command as a permanent rule in `.claude/settings.local.json`. If the command had a password or token in it, the secret is saved too. The tool hides this file from git only on your own machine, so a new clone, or a file already committed, can still expose it. Security firm Apiiro found 1,122 secrets in these files, across 63 organizations. GitGuardian found 31,088 on public GitHub, and 5,343 still worked. Normal secret scanners missed many because the secrets sat inside shell commands.

**Why it matters:** Any tool that records what an AI ran can also record your secrets. Keep them in environment variables, not typed into commands.

**New words:** **Git ignore** — a list of files git should never upload · **Credential** — a password or key that proves who you are · **Environment variable** — a named setting kept outside your code

## 3. AWS Lambda can now run AI models on GPUs
*InfoQ* · Cloud / AI

**In one line:** Amazon's "run code on demand" service now supports graphics chips, so you can run AI models without managing servers.

**What happened:** Lambda lets you run small pieces of code when something happens, without setting up machines. Now those functions can run on GPU machines, which are chips good at AI work. You package your code as a container image and Lambda handles setup and scaling. Up to 48 requests at once can share one copy of the model in the GPU's memory. In one test, one environment served all 48 requests at once, and none of 417 calls failed. There are limits: new accounts start with zero GPU quota, and it handles event-style jobs, not web-style functions yet. Spinning up new machines takes tens of seconds, so it suits steady work better than sudden spikes.

**Why it matters:** Teams can run their own AI model behind queues or uploads without running GPU servers themselves.

**New words:** **GPU** — a chip that does many small calculations at once, great for AI · **Inference** — using a trained AI model to get an answer · **Container image** — a packed box holding your code and everything it needs

## 4. Google plans a safe room for AI agents that never holds their keys
*InfoQ* · Cloud / AI

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-23/4.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-23/4.mp4"></video>

**In one line:** Google announced Agent Compute Engine, which runs AI agents in sealed mini-computers with no passwords inside.

**What happened:** The service runs each agent in a "microVM", a tiny, isolated virtual computer. The agent's "brain" runs outside, and only sends commands in. Passwords and tokens stay outside too, and a gateway adds them to requests when needed. So even a confused agent can't leak what it never has. Idle agents can be paused and resumed quickly. It isn't available yet: a preview is planned "in the coming months", and there's no price. Google also offers Agent Substrate, an open-source version that runs on Kubernetes.

**Why it matters:** It's a direct answer to stories 1 and 2: keep secrets out of places where an AI can touch or record them.

**New words:** **MicroVM** — a very small virtual computer that is walled off from others · **Sandbox** — a closed space where risky code can run safely · **Gateway** — a checkpoint that handles requests on your behalf

## 5. "The harness is the new operating system" for AI agents
*InfoQ (QCon SF keynote)* · AI

**In one line:** A keynote argued that the code around an AI model matters as much as the model itself.

**What happened:** The speaker called everything around the model, such as its tools, memory, permissions and feedback, the "harness". Model plus harness equals agent. He compared harness parts to what operating systems do. For example, give the model a pointer to information, not the whole thing. One study found GPT-4 Turbo solved 11.0% of coding issues with a plain shell but 18.0% with a tool built for agents. Errors also pile up: with 95% success per step, a 20-step job works only 36% of the time. His advice was that boundaries enforce, while instructions only guide.

**Why it matters:** If an agent keeps failing, improving the harness may help more than switching models.

**New words:** **Harness** — everything around an AI model that lets it act · **Context window** — how much text a model can look at at once · **Benchmark** — a standard test to compare tools

## 6. GitHub Actions accepts YAML that isn't actually valid
*Yossarian.net* · Backend / DevOps

**In one line:** GitHub's automation tool accepts some files that break the official YAML rules, which trips up other tools.

**What happened:** YAML is a format for settings files. Its rules say a multi-line quoted value inside a list must be indented by at least one extra space. A real workflow broke that rule by one space, and GitHub Actions ran it anyway. A security checking tool called zizmor then rejected the file, because it followed the rules properly. The author thinks GitHub uses an old YAML parsing library that has this gap, and even the newest version of it still does. So some real workflows can't be read by strictly correct tools.

**Why it matters:** When one big platform is lenient, every other tool has to copy its mistakes.

**New words:** **YAML** — a text format for settings and configuration · **Parser** — a program that reads a file and understands it · **Workflow** — a list of automatic steps GitHub runs for your project
