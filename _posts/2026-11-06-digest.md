## 1. GitHub rebuilt how it stores code so thousands of AI agents can push at once
*GitHub Blog* · Backend


**In one line:** GitHub redesigned the system behind Git storage so one repository can take thousands of saves per second.

**What happened:** Today the busiest repositories get a few dozen writes per second. GitHub expects AI agents working in parallel to turn those bursts into a steady stream. So it built a new design called "Rubicon". The code files themselves go into Azure Blob Storage (a huge online filing cabinet). A small, separate service called Ref-CAS keeps track of which branch points to which commit, and it only locks the branches being changed. Background workers tidy up and merge the many small files, so the servers answering requests stay fast. In tests, 5,000 agents sent 7,200 pushes per second to one repository while reads stayed fast.

**Why it matters:** As agents write more code, a single project gets far busier. Git still works the same for you, but the plumbing under it had to change.

**New words:** **Git** — a tool that records every version of your code · **Repository** — a project folder with all its history · **Push** — sending your new changes to a shared copy · **Compare-and-swap** — "change this only if it still has the value I expect" · **Compaction** — merging many small files into fewer big ones

## 2. A long password could let anyone into some Alpine Linux servers
*Alpine Linux* · Security


**In one line:** A bug let attackers log in over SSH with no password by sending a very long one.

**What happened:** SSH is the common way to log in to a server remotely. On Alpine Linux, when the SSH server runs without a feature called PAM, it checks passwords with a function called crypt(). That function returns the text `*` as an error when the password is longer than 256 bytes. Accounts with no password also store `*`, so the two "matched" and the login worked. The attacker needs the name of such an account, and the machine needs at least one other account with a normal password. Alpine says to update openssh and restart sshd, or turn off password logins until you can.

**Why it matters:** Upgrading the package alone is not enough, because the old SSH server keeps running until restarted.

**New words:** **SSH** — a secure way to log in to another computer · **sshd** — the program on a server that accepts SSH logins · **Hash** — a scrambled form of a password that is stored instead of the password · **Salt** — random text added before hashing

  B --> C[Stored field is also *]
  C --> D[Match: login allowed]
</pre>

## 3. Shopify lets AI agents test its phone apps without a phone
*Shopify Engineering* · Mobile

**In one line:** Shopify built "Reflex", a way to run and test app screens from a terminal, with no simulator.

**What happened:** Shopify is rebuilding its apps natively, once in Swift for iPhone and once in Kotlin for Android. Every screen's logic lives in a "ViewModel" that takes actions in and gives state out. A small command-line tool reads that state as JSON and sends actions, so an agent can walk through the app without drawing anything. One test file runs on both platforms, so they stay in sync. Shopify's motto is "share the test, not the code". Over 1,700 behavior tests finish in about four minutes on CI.

**Why it matters:** Agents write code quickly, but checking it was slow. Fast, device-free tests close that gap.

**New words:** **ViewModel** — the part of an app that holds what a screen shows and what it can do · **Headless** — running without a visible screen · **CI** — automatic test runs when code changes · **Fixture** — fake data used in a test

## 4. Cloudflare: websites can't tell who is behind an AI agent
*Cloudflare Blog* · Security

**In one line:** When an AI agent shops or browses for you, the website only sees the agent, not you.

**What happened:** Cloudflare compares an agent to a personal assistant, Ezra, who runs errands for four clients. The shop can't tell whose order is whose. If one client misuses Ezra, the only option is to ban Ezra, which hurts everyone. Cloudflare says sites need identity, reputation and accountability, and it names ideas such as Web Bot Auth (agents sign their requests). It is starting a group called Trusted Agent Delegation. Cloudflare customers can now see which agents visit, set rules per agent, and link an agent's login to a hashed user ID.

**Why it matters:** Simply blocking agents will stop working once most traffic comes from them.

**New words:** **Agent** — an AI that carries out tasks for a person · **Intermediary** — something between you and a website · **Web Bot Auth** — a way for a bot to sign its requests to prove who it is · **IETF** — the group that writes internet standards

[Read the full post →](https://blog.cloudflare.com/trusted-agent-delegation/)

## 5. How Dropbox lets an AI agent change your files safely
*Dropbox Tech* · AI

**In one line:** Dropbox gave its agent a locked-down workspace, permission checks, and a per-conversation undo.

**What happened:** Two engineers had side projects letting coding agents work on Dropbox files. Dropbox merged them. Each chat gets its own fresh virtual machine, started from a saved snapshot, which comes online in tens of milliseconds. Passwords and keys stay outside it, and a separate process checks every request and the person's permission. Dropbox records which conversation made each file version, so one chat's changes can be undone without touching other edits. If someone edited a file since, the restored version is saved as a renamed copy.

**Why it matters:** An agent that edits real files must be limited, watched, and reversible.

**New words:** **Sandbox** — an isolated space where a program can't affect the rest of the system · **Virtual machine** — a pretend computer running inside a real one · **Snapshot** — a saved state you can restore quickly · **Credentials** — keys or passwords that unlock services
