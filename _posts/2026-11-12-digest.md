## 1. Shopify rewrote its whole mobile app in 12 weeks, mostly with AI agents
*Shopify Engineering* · Mobile / AI

**In one line:** Thirty engineers rebuilt the Shopify app as two native apps, and the hard part was everything around the code, not the code.

**What happened:** Shopify moved its app from React Native (one shared codebase) to Swift for iPhone and Kotlin for Android. The app has more than 300 screens. Thirty engineers worked in pairs, and AI agents wrote most of the code. Before the rewrite, a small group built the "rails": one shared architecture for both phones, a tool that loads any screen in milliseconds, and checks that fail when code drifts. The old app served as the spec, so agents checked each small step against it. Once code got fast to write, the slow parts became review, merging, machines and teamwork. Agents now do the first code review and humans do the last one.

**Why it matters:** Speeding up code writing just moves the traffic jam somewhere else. The results: Android launch time dropped about 50%, and Android crash-free sessions rose from 99.66% to 99.98%.

**New words:** **React Native** — a way to build phone apps for iPhone and Android from one shared codebase · **Native app** — an app built specially for one kind of phone · **CI** — an automatic robot that checks every code change · **PR (pull request)** — a proposed code change waiting for review

## 2. Shopify built one AI model to power both search and "you might like" picks
*Shopify Engineering* · AI / Backend

**In one line:** One model learned from both what people search for and what they buy, and it now suggests products better.

**What happened:** Shopify has billions of products. Search and recommendations both try to guess what a shopper wants, so Shopify trained one shared model on both. Instead of raw product ID numbers, each product gets a short code of three tokens, so similar products share parts of their codes. Think of it like a library shelf label. The team also gave extra weight to "first purchases" so the model learns to suggest new things, not only repeat old ones. On the Shop app home feed, orders went up 7.95%. Search quality improved too.

**Why it matters:** Training search and recommendations together made each one better, and the model is fast enough to run live while you wait.

**New words:** **Embedding** — a list of numbers that captures what something means · **Semantic ID** — a short code made of tokens that describes a product's meaning · **Candidate generator** — the first step that picks possible products before a later step sorts them · **Reinforcement learning** — training by giving feedback on how good the answers are

## 3. Netflix's AI fact-checker for show descriptions got cheaper and more accurate
*Netflix Tech Blog* · AI

**In one line:** Netflix checks that the short description of each show is true, and a new design cut the cost by about half.

**What happened:** Every show has a short summary, and it must be factual. Some summaries are wrong in a sneaky way: each sentence is true, but the picture it paints is misleading. Netflix used to ask a big AI model the same question five times on very long inputs. That was costly. The new design uses two specialised judges: one checks if the text is literally true, and one checks if it misleads a new viewer. Easy cases pass quickly, like bags at airport security. Only the unsure cases get extra checks.

**Why it matters:** Cost per summary fell 52.4% on show-level summaries, and the system now catches more bad ones (0.77 to 0.86 of them).

**New words:** **Synopsis** — a short summary of a show · **LLM** — a large language model, the kind of AI behind chatbots · **Recall** — out of all the bad items, how many you caught · **Rationale** — the reasons the AI gives for its answer

## 4. When AI writes your code and your tests, who checks the AI?
*Martin Fowler's site (by Matteo Vaccari)* · Engineering practice

**In one line:** An essay says tests should be simple tables of data that AI can't easily rewrite.

**What happened:** The author talked to 26 developers using AI coding agents. They said they did not trust their tests, because the AI keeps changing the tests along with the code. Tests full of "mocks" (fake helpers) often just prove the code does what it already does. The author suggests "customer tests": plain checks of what the software should do, written as data (input and expected output) in a simple table or file. A small test runner reads the data. Humans can read it easily, and it is harder for an AI to quietly change.

**Why it matters:** If AI writes the code, humans become the customers, and they need a clear contract that the AI cannot easily bend.

**New words:** **Mock** — a fake stand-in used in a test · **Customer test** — a test written in the customer's language about what the software should do · **Regression** — something that used to work and breaks later · **DSL** — a tiny made-up language for one job

## 5. Pinterest and Intel make an open-source "where is my server slow?" tool
*InfoQ* · Backend / DevOps

🎬 [Watch: Visualizing Performance with Flame Graphs (Brendan Gregg, USENIX ATC 2017)](https://www.youtube.com/watch?v=D53T1Ejig1Q)

**In one line:** Pinterest extended an open-source profiler so engineers can see why services are slow across hundreds of thousands of machines.

**What happened:** A profiler shows which parts of a program use the most time. Pinterest had many separate tools for Java, Python, C++ and more, so results were hard to combine. With Intel, it extended gProfiler, which merges them into one picture called a flame graph. Engineers can now switch profiling on remotely, without logging in to machines. New features include hardware details like cache misses and "wall-time" profiling, which shows when a service is just waiting. The idle agent uses under 1% CPU.

**Why it matters:** At Pinterest's size, even a tiny speed-up saves a lot of money.

**New words:** **Profiler** — a tool that shows where a program spends its time · **Flame graph** — a chart where wider bars mean more time spent · **Wall-time** — real elapsed time, including waiting · **Fleet** — the whole group of servers a company runs

## 6. A false smoke alarm almost flooded Jane Street's datacenter
*Michael Bacarella's blog* · Infrastructure / War story

**In one line:** A dusty building job set off a smoke alarm, which switched off the cooling and nearly caused a sprinkler flood.

**What happened:** Contractors next door kicked up dust and tripped the smoke alarm in the datacenter. The alarm is wired to turn off the air conditioners so air does not feed a fire. With no cooling, the servers heated up, and the sprinklers go off when the air gets hot enough. The author ran to the office and pulled the power cord on every device. The room reached about 143.6°F and stopped. Afterwards, the team wrote a monitor that asks every server for its temperature each minute and alerts when the average is high.

**Why it matters:** Safety systems can interact in surprising ways, and an alert on "everything is a bit warmer" catches problems that single sensors miss.

**New words:** **Datacenter** — a room full of servers · **CRAC unit** — an air conditioner built for computer rooms · **UPS** — a battery backup for power · **Monitor** — a program that watches and alerts
