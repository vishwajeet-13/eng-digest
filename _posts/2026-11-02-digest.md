## 1. A company picked "4" as a secret key, and the whole internet had to patch
*Cloudflare Blog* · Security

**In one line:** A company trusted to vouch for websites made its secret keys so weak that anyone could work them out.

**What happened:** Websites prove who they are with certificates. A certificate authority (CA) is a company that signs those certificates, a bit like a passport office. A CA named eMudhra was supposed to pick a secret 115-digit number as its key. For one key, it picked the number 4. The other seven keys were also tiny numbers. Anyone could work out the private keys from the public certificates, then make fake certificates for any website. Cloudflare patched its important systems within hours. It then saw about 22,000 handshakes using the weak keys, and about 160 of them used forged certificates. It found no sign that attackers used them to spy on Cloudflare's traffic. But when Cloudflare tested visitors, more than half of the big networks it checked still trusted the bad keys. Bots, old browsers and Android WebView lagged most.

**Why it matters:** Your device keeps a list of companies it trusts. If one of them fails, you must update your software to stop trusting it.

**New words:** **Certificate authority** — a company that signs certificates to prove a website is real · **Private key** — a secret number that only the owner should know · **Patch** — a software update that fixes a problem

## 2. Meta uses AI to write tests that try to break new code
*Engineering at Meta* · AI / Testing

**In one line:** Meta's AI writes small tests for risky code changes overnight, to catch bugs before the code goes live.

**What happened:** Engineers at Meta change code all day, and old-style testing cannot keep up. Meta built a system called Catching JiTTests ("just-in-time tests"). It picks risky code changes from the previous day. An AI then writes tests that are meant to fail if the change behaves differently than intended. Other AI models and a set of fixed rules then judge which failures are real bugs and which are false alarms. Engineers are only contacted for the best candidates. Meta calls this "human-on-the-loop": people set the rules and check overall results, instead of reading every output. In the first half of 2026 it helped catch 74 serious privacy bugs before release. About 60% of the reports engineers reviewed were true positives.

**Why it matters:** As AI helps people write code faster, checking that code has to speed up too.

**New words:** **Test** — a small program that checks other code works · **Diff** — the list of changes someone made to code · **False positive** — a warning that turns out to be wrong · **Human-on-the-loop** — people set goals and review results, rather than check every item

## 3. How a sandbox escape could have exposed ChatGPT accounts
*Simon Willison's Weblog* · Security

**In one line:** Researchers chained several small flaws to break out of a safe box in ChatGPT and read other users' private data.

**What happened:** ChatGPT can show small web apps inside a locked-down box called a sandboxed iframe. The box is meant to keep that code away from your account. Researchers found that a maths-keyboard library on the page accepted messages from the box and put the text straight into the page as HTML. That let them add a new frame with no sandbox. The site's rules only allowed scripts from a few trusted places, and one was YouTube. A YouTube feature could be tricked into sending back JavaScript that then ran. With that, an attacker could build a share link that, when opened by a signed-in user, would take their private data. OpenAI fixed it and paid a $5,000 bounty.

**Why it matters:** Strong walls still fail when small gaps line up.

**New words:** **Sandbox** — a locked box where untrusted code runs with limited power · **iframe** — a web page shown inside another page · **XSS** — tricking a site into running an attacker's code · **Bug bounty** — a reward for reporting a security hole

[Read the full post →](https://simonwillison.net/2026/Oct/31/how-we-took-over-chatgpt-accounts/)

## 4. Netflix treats broken GPUs like a team problem, not a single-machine problem
*InfoQ (about Netflix)* · Cloud / AI

**In one line:** Netflix built automatic health checks and repairs so huge AI training jobs keep running when hardware fails.

**What happened:** Training one AI model can take weeks on hundreds of GPUs (the chips that do the heavy maths). They all work in step, so one bad GPU can slow or stop everyone. Netflix found a GPU can look healthy and still fail once it does real work. So it runs deeper checks, and a check that hangs counts as a failure. Repairs go step by step: first stop giving the machine new work, then drain it, then reset or replace it. Jobs save progress often (checkpoints), so they can restart from the last good point. Netflix reports over 99.95% GPU-node availability, and job success rising from about 98% to over 99.5%.

**Why it matters:** At big scale, hardware will fail, so the system must be built to recover.

**New words:** **GPU** — a chip good at doing many calculations at once · **Checkpoint** — a saved snapshot of progress · **Kubernetes** — software that manages many machines and programs · **Drain** — move work off a machine

## 5. Netflix gives some programs a whole computer to themselves
*InfoQ (about Netflix)* · Cloud / Backend

**In one line:** Netflix added a mode that runs one task alone on its own server, so noisy neighbours cannot slow it.

**What happened:** Netflix runs millions of containers a week, and many share one machine. Sharing can hurt: one busy program can use up the cache, memory speed or network, and slow the others. For some streaming jobs, that can mean minutes of recovery. Netflix tried tuning the shared setup, but said it only narrows the gap. It also rejected lighter virtual machines such as Firecracker, for reasons such as nested virtualization not being ready on its instance types. Instead, single-tenant Titus picks the smallest server that fits the task and puts only that task on it. The cost is slower starts, since a fresh server takes tens of seconds to boot.

**Why it matters:** Sharing saves money, but some work is worth paying extra to keep alone.

**New words:** **Container** — a packaged program that runs in a walled-off space · **Single-tenant** — one user or task per machine · **Latency** — waiting time · **Noisy neighbour** — a program that hogs shared resources

[Read the full post →](https://www.infoq.com/news/2026/10/netflix-titus-kubernetes-microvm/)

## 6. DoorDash made its AI grocery reorder 8x faster by doing the thinking ahead of time
*InfoQ (about DoorDash)* · AI / Backend

**In one line:** DoorDash cut reorder wait time from about 16 seconds to 2 by preparing lists in advance.

**What happened:** DoorDash's assistant can build a grocery list from what you bought before. At first it rebuilt that list from scratch each time, which was slow. Now a nightly-style batch job reads 90 days of purchases and uses an AI model to spot items you buy regularly. Fixed checks validate the result, and the list is stored. When you ask, the app fetches the list and matches each item to what the store has right now. Simple edits, such as changing a quantity, skip the AI entirely. DoorDash reports that shopping list views doubled and the flow's order rate rose about 34%.

**Why it matters:** Not every step needs a slow AI call in the middle of a request.

**New words:** **Latency** — how long you wait for an answer · **Batch** — work done ahead of time in bulk · **LLM** — a large language model, the AI behind chatbots · **Catalog** — the store's current list of products

## 7. Is the cloud really "sold out" through 2027?
*InfoQ (about AWS)* · Cloud

**In one line:** Amazon's CEO said AWS's big reserved capacity is mostly sold out through 2027, but experts say the headline is misleading.

**What happened:** Andy Jassy said AWS's large committed capacity is largely sold out through 2027, with a good chunk of 2028 taken. He said AWS still keeps some room for on-demand use. Analyst David Linthicum replied that pre-booked giant blocks are not the same as being unable to rent computers today. Some developers say they have had trouble getting even ordinary servers lately, often for build pipelines. Another commenter warned that people may now reserve more than they need, which defeats the idea of paying only for what you use.

**Why it matters:** If cloud capacity is tight, teams may need to plan and reserve earlier.

**New words:** **Capacity** — how many computers a cloud has to rent out · **On-demand** — renting computers by the hour without booking ahead · **Reservation** — paying to hold capacity for later
