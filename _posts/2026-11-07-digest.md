## 1. Datadog found a year-old hidden bug by checking its live system against its design rules
*Datadog Engineering* · Backend

**In one line:** Datadog built a tool that keeps checking a running system against its written design, and it caught a bug that tests missed.

**What happened:** Datadog's event database, Husky, had a formal "spec" — a precise rulebook written in a language called TLA+ that says what the system may and may not do. Over time the real system changed, and the rulebook could quietly stop matching it. So Datadog built FETCh, which turns the rulebook into small Rust programs that watch real logs and raise an alarm when the system breaks a rule. FETCh ran beside the routing service on more than 1,300 pods and used about 2% CPU. It flagged conflicting "placements" that had been saved for about a year after a special-case change. Think of a referee who never leaves the game, instead of one who only checked the rules at kickoff.

**Why it matters:** Two conflicting placements would have crashed the backfill system during a recovery, and normal tests could not trigger that rare case.

**New words:** **Formal specification** — a precise, math-style description of how a system must behave · **TLA+** — a language for writing such specifications · **Runtime monitor** — a small program that watches a live system and flags rule breaks · **Drift** — when the real system slowly stops matching its description

## 2. A food-ordering platform cut compute costs up to 64% by sharing servers between brands
*AWS Architecture Blog* · Cloud


**In one line:** OrderServ stopped giving each restaurant brand its own set of servers and now shares one set, with software keeping each brand's data apart.

**What happened:** OrderServ, run by Cognizant, gave every brand its own cluster with 21 small services, so costs grew with each new brand. The team moved to one shared cluster. A shared code library tags every request with a brand ID and refuses to touch data without it. They also swapped AWS Fargate for EC2 machines that are kept pre-started but stopped ("warm pools"). New capacity now arrives in 30–60 seconds instead of 5–7 minutes, which matters when promotions spike traffic 5–10 times within minutes. Compute cost dropped 47–64% depending on the savings plan.

**Why it matters:** Sharing infrastructure saves money, but only if the isolation between customers is built carefully in code.

**New words:** **Multi-tenant** — many customers sharing one system, kept apart by software · **Warm pool** — servers prepared in advance and kept stopped until needed · **Cluster** — a group of machines that run an app together

## 3. GitHub Actions can now lock every dependency to an exact version
*InfoQ* · Security


**In one line:** A new lockfile makes your build pipeline run the exact code you approved, even if someone changes a tag later.

**What happened:** Workflows often use shared building blocks written like `actions/checkout@v4`. A tag like `v4` can be moved, so a hacked action could slip bad code into your pipeline. Pinning to a full commit ID helps but is hard to read and misses the blocks inside blocks. GitHub's lockfile (`.github/workflows/actions.lock`) records the exact commits for direct and nested dependencies. The runner uses those commits no matter where tags point. Dependabot updates the lockfile in the same pull request, and admins can require it.

**Why it matters:** It closes a known supply-chain gap, but GitHub notes a lockfile does not prove the code is safe, so reviews still matter.

**New words:** **Lockfile** — a list of the exact versions to use · **Commit** — one saved snapshot of code · **Supply-chain attack** — hacking a tool you depend on instead of you directly · **Dependabot** — a bot that proposes dependency updates

  B --> C[Runner runs that commit]
  C --> D[Tag changes are ignored]
</pre>

## 4. Cloudflare explores private, quantum-safe "tokens" for the web
*Cloudflare Blog* · Security

**In one line:** Cloudflare is designing the next version of Privacy Pass so it still works once quantum computers can break today's locks.

**What happened:** Privacy Pass lets a site limit abusive visitors without CAPTCHAs or tracking. A visitor gets tokens that the site can't link back to them. Today's tokens use maths that a future quantum computer could break, so an attacker could forge tokens. The privacy part stays safe even then. The catch is size: one quantum-safe signature is 2,420 bytes versus 64 bytes today. Cloudflare describes a new design called MOLE using VOLE-in-the-Head proofs and a signature scheme called UOV. Its estimates are about 4.3 KB per redemption, with each operation taking a few milliseconds. Security proofs are still needed.

**Why it matters:** Quantum-safe tools are bigger, so web systems must be redesigned to carry the extra weight.

**New words:** **Post-quantum** — built to resist quantum computers · **Blind signature** — a signature given without the signer seeing the message · **Zero-knowledge proof** — proving something is true without revealing it · **Token** — a small pass redeemed for access

[Read the full post →](https://blog.cloudflare.com/vole-mole/)

## 5. TypeScript 7.1 beta brings back the compiler API
*InfoQ* · Frontend

**In one line:** The fast new TypeScript compiler, written in Go, now lets tools plug in again and checks Vue code much faster.

**What happened:** TypeScript 7.0 arrived in July with a Go-based compiler but dropped the API that other tools used. Vue, Svelte and Astro tools were stuck on version 6. The 7.1 beta restores an API split into smaller parts and adds "content mappers", plugins that show TypeScript a virtual view of files like `.vue`. In one migration of 581 Vue components, type checks fell from 14.19 to 3.10 seconds. The team expects stable around late November. Vue and Svelte users should keep TypeScript 6 and 7 side by side for now.

**Why it matters:** Speed gains reach more developers once framework tools can use the new compiler.

**New words:** **Compiler** — a tool that checks and translates code · **API** — a set of hooks other programs use to talk to a tool · **Beta** — a test version before the final release

## 6. Yelp mixed native and server-driven screens for its AI assistant
*InfoQ* · Frontend

**In one line:** Yelp keeps the chat's input and navigation built into the app, while the server controls what the conversation area shows.

**What happened:** With server-driven UI, the backend says what the screen shows, so changes need no new app release. Yelp's CHAOS framework lacked text input and network requests that the Assistant needed. Instead of extending it, Yelp kept navigation and message input native and used CHAOS for the conversation. The app fetches the layout once, then new messages arrive as events that update the view. The server can also send actions, like disabling input when a request is finished. Yelp says teams still had to learn two systems.

**Why it matters:** A hybrid design let Yelp ship faster, and it reused the Android version for another pilot.

**New words:** **Server-driven UI** — screens described by the server, not fixed in the app · **Native** — built with a phone's own tools · **Event** — a small message saying something happened
