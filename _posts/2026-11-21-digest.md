## 1. Signal blocks AI assistants on your phone from reading your private chats
*Signal* · Security

**In one line:** Signal is stopping the AI helpers built into phones from capturing what is on your Signal screen.

**What happened:** New phone systems have AI helpers, like Gemini on Android and Siri AI on iOS 27, that "read" your screen to answer your questions. That means your private messages could be captured and stored somewhere Signal cannot control. Signal now blocks screenshots in the app on iOS 27, and on Android it turns on "Screen security" when it sees an AI assistant trying to read the screen. You can switch this off in settings, but then your chats may be exposed to those assistants. Signal says the fix is incomplete. It cannot do this on macOS, and agents could still reach data in other ways, such as through files on the device.

**Why it matters:** Signal says phone makers give app builders no proper way to opt out of AI access. It asks Apple, Google and Microsoft for an easy opt-out and clear documentation.

**New words:** **AI agent** — an AI that acts for you, not just chats · **Operating system** — the main software that runs a phone or computer · **Screenshot blocking** — stopping the screen from being copied as a picture

## 2. AWS releases a free copy of itself that you can run on your laptop, built entirely by AI agents
*InfoQ* · Cloud



**In one line:** Amazon released a free tool that pretends to be more than 200 of its cloud services, so you can test your apps locally.

**What happened:** AWS Emulator is a free program that acts like AWS on your own computer. It is a single Rust program, and AWS says thousands of AI agents wrote every line of it. The idea started as a three-line prompt: write tests from the AWS command line, make them pass on real AWS, then build a fake version that passes the same tests. Three teams of agents work together: one keeps the tests, one finds problems and one fixes them. Every fix must pass a gate of checks before it is merged. Early outside tests found about 60 to 70 percent of checks passing for some services, and only about 20 percent for CloudFormation.

**Why it matters:** Testing locally is faster and free. But AWS warns that the emulator does not check security permissions like the real AWS, so you must not use it to test whether your app is secure.

**New words:** **Emulator** — a fake copy of a service that behaves like the real one · **Fidelity** — how closely the copy matches the real thing · **Merge gate** — automatic checks a change must pass before it joins the code

## 3. How Netflix lets an AI plan your TV browsing without letting it run wild
*Netflix Tech Blog* · AI

**In one line:** Netflix built a "plan first, then run" system so an AI can help you find shows safely on your TV.

**What happened:** AI Discover is a new Netflix TV tab where you pick a theme, like "Quick Watches", and get matching titles. Behind it is a controller and an executor. The controller makes a plan, which is a list of approved steps, and checks it before anything runs. The executor then runs the steps, in parallel when it can. If the AI planner is slow or its plan fails a check, Netflix uses a tested plan instead. Rules about safety and maturity ratings are enforced in code, not left to the AI's prompt. Because generation takes seconds, the TV gets an instant reply and the result arrives later.

**Why it matters:** At Netflix's size, rare AI mistakes happen many times a day. Letting code, not the AI, decide what is allowed keeps results reliable and safe.

**New words:** **Agent harness** — the code that decides when to call an AI and checks what it returns · **Prompt injection** — tricking an AI with hidden instructions · **Asynchronous** — you get an answer later, without waiting while it works

## 4. Google gives away the tools that keep AI agents' code locked in a box
*InfoQ* · Cloud



**In one line:** Google donated Agent Substrate and gVisor, two tools for running AI agents safely, to the open-source CNCF.

**What happened:** AI agents run code they wrote themselves, which can be risky. They also sit idle 90–95% of the time, waiting for an AI model or a person, yet still hold memory and files. Agent Substrate splits an agent's saved state from the machines that run it. When an agent wakes up, it gets a ready machine and its state is restored in under 500 milliseconds. gVisor adds a safety wall by catching the agent's requests to the main system and handling them itself. This is like a guard between a visitor and the building's control room.

**Why it matters:** Kubernetes was built for apps that run for a long time. Agents start, pause and stop all the time, so they need their own kind of setup.

**New words:** **CNCF** — a non-profit that hosts open cloud software · **Sandbox** — a walled-off space where risky code cannot harm the rest · **System call** — a request a program makes to the operating system · **Pod** — the small unit Kubernetes uses to run a program

## 5. Shopify checks its mobile apps for security holes every day, now that AI writes code 11 times faster
*Shopify Engineering* · Security

**In one line:** Shopify made a "map" of everything risky in its apps and reviews every change to it each weekday.

**What happened:** Shopify's team now changes about 434,000 lines of code a week in its mobile app, up from about 39,000 a year ago. To keep up, it keeps a list of risky spots, like deep links and WebViews, each with a verdict such as "Fix" or "Secure". Each area has a "skill" that holds best practices and lessons from past incidents. Instead of asking an AI to review the whole app, it reviews one item at a time with only the code that item touches. Every weekday, models look at what changed, update the map and post a summary. Agents also read security news and ping the team only if something affects them.

**Why it matters:** Small, focused reviews give clear answers that can be checked. Each bug found makes the next check stronger.

**New words:** **Attack surface** — all the places an attacker could try to get in · **Deep link** — a link that opens a specific screen inside an app · **WebView** — a mini web browser inside an app

## 6. AI and math tools find bugs in two widely used Raft libraries
*Antithesis* · Backend

**In one line:** Antithesis used AI to check, with maths, that two popular Raft libraries are safe, and found bugs on the way.

**What happened:** Raft is a method that lets several servers agree on one shared record, even if some crash. Libraries from etcd and HashiCorp use it. The team had AI write a model of each library in TLA+, a language for describing designs. Test runs with injected faults, such as network cuts and crashes, then checked the real code against the model. They found and patched 7 bugs across the two libraries, then proved key safety rules, like "at most one leader per term". Each library cost under $1,200 in AI tokens and about 2,000 hours of computing. The proofs cover the model, not the code itself, and the work leaves out some features.

**Why it matters:** It is an early sign that AI could make formal proofs cheaper. The authors call it a medicine tested on mice, not yet on humans.

**New words:** **Raft** — a way for servers to agree on the same data · **TLA+** — a language for describing how a system should behave · **Fault injection** — breaking things on purpose to see what happens · **Formal proof** — a maths proof that a rule always holds
