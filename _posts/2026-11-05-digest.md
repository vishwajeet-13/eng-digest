## 1. Anthropic built its own "Git" because AI writes too much code
*ByteByteGo* · Backend


**In one line:** Anthropic's tools for storing and sharing code could not keep up with how fast AI writes it, so a small team built a new system called Scion.

**What happened:** Anthropic keeps most of its code in one big shared place called a monorepo. Merged changes grew from about 2,500 a day in May 2026 to more than 30,000 a day by September. Its automated systems do about 25 million "checkouts" a day, which means copying a version of the code to a worker. Git, the usual tool, makes each worker keep its own full copy, and that got too heavy. At one point Anthropic ran several hundred mirror servers just to share the code. Scion flips this. A central service answers questions and makes the changes, and workers only keep a small cache of what they need. Think of a library where you ask the librarian instead of owning every book.

**Why it matters:** When AI writes code faster than people ever could, the boring tools around code become the bottleneck.

**New words:** **Monorepo** — one shared storage place for many projects' code · **Checkout** — getting a working copy of one version of the code · **Content-addressing** — naming a file by a fingerprint of its contents, so the same name always means the same data · **Cache** — a nearby copy kept so you don't fetch it again

## 2. How Figma safely runs thousands of AI sandboxes
*Figma Engineering Blog* · Cloud


**In one line:** Figma built a platform called Nimbus that hands out locked-down boxes where AI-written code can run safely.

**What happened:** Figma's AI tools write code that must run somewhere safe, because the code is not trusted. That needs tens of thousands of "sandboxes" (sealed boxes). Product teams just fill in a short settings file, and Nimbus does the rest. To be fast, Nimbus keeps a pool of ready-to-use "warm" sandboxes, which cut start-up time by 90%. Availability rose from 99% to 99.95%. For safety, code inside a sandbox may read from any website but can only send data to hosts on an approved list. Secrets are scrambled inside the box and only swapped for the real value on their way to the right place.

**Why it matters:** Letting AI run code is only safe if the box around it is strict, quick to start and works even when a cloud provider has trouble.

**New words:** **Sandbox** — a sealed space where untrusted code can run without touching anything else · **Warm pool** — sandboxes already started and waiting for use · **Sidecar** — a helper container that runs next to the main one

## 3. Go gets a safer, faster way to read JSON
*The Go Blog* · Backend

**In one line:** The Go language now has a new, stable JSON package that is stricter and up to 10 times faster at reading data.

**What happened:** JSON is the plain-text format most websites and apps use to swap data. Go's old JSON package had problems that could not be fixed without breaking old programs. It accepted broken text and repeated names in the same object, which has been used in attacks before. So the team made a new version, `encoding/json/v2`, available in Go 1.27 after about six years of work. It rejects bad text and duplicate names, and reading data is up to 10 times faster. Old code keeps working, and the two versions can work together.

**Why it matters:** Millions of programs read JSON, so being safer and faster by default helps a lot of software.

**New words:** **JSON** — a simple text format for sharing data · **Marshal / unmarshal** — turning program data into JSON text and back · **Streaming** — handling data piece by piece instead of all at once

## 4. A tiny change made SQLite 12,000 times slower
*Dennis Forbes* · Backend

**In one line:** A rewrite of basic text functions in the Zig toolchain made a database crawl, because of a mistake as old as programming.

**What happened:** A developer's chess service took minutes to save about 40,000 records into SQLite. The cause was in Zig's compiler, used to build SQLite for Linux. Zig is rewriting standard text functions in its own language. In the new versions, each call first measures the whole text. A tokenizer, which reads text in small steps, calls them over and over. So it re-measures the full text each time. This is the "Shlemiel the Painter" trap, where you keep walking back to your paint can. For a 1.2MB file it was about 12,000 times slower. The developer moved Linux builds into containers as a workaround.

**Why it matters:** Small hidden costs repeated many times can grind a program to a halt, and a profiler helps find them.

**New words:** **Quadratic slowdown** — work that grows with the square of the input, so double the data means four times the time · **Tokenizer** — code that cuts text into small pieces to understand it · **Cross-compile** — building a program on one kind of computer to run on another

## 5. Docker's five ways AI agents can go wrong
*InfoQ* · Security

**In one line:** Docker lists five risks of AI agents that act on their own, and says the fix is to fence them in.

**What happened:** An AI agent can browse, run code and call tools without asking each time. Docker names five risks: prompt injection, tool misuse, too much freedom, leaked credentials and data leaking out. Prompt injection means hiding instructions in a web page or file that the agent reads. Docker says an agent cannot reliably tell real instructions from fake ones, so the answer is to limit what a tricked agent can reach. It suggests short-lived credentials for agents, approved lists for network access, and running each agent in a throwaway microVM. Examples include an agent that deleted a developer's home folder.

**Why it matters:** Assume an agent may be tricked, and design so one bad decision cannot cause big damage.

**New words:** **Prompt injection** — hiding orders in text an AI will read · **MicroVM** — a very small, quick virtual computer used for isolation · **Egress** — data leaving your network
