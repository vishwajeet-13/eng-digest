## 1. Google launches Gemini 4 Hydrogen, a fast model for everyday work
*Google* · AI

**In one line:** Google released a quicker, cheaper AI model and put it into its apps, its developer tools and Google Search.

**What happened:** Google has three Gemini 4 models. Carbon and Argon are the big "deep thinking" ones. Hydrogen is the fast one, made for everyday coding and for AI agents (programs that take steps on their own). Google says Hydrogen scores 51 on the Artificial Analysis Intelligence Index, just above Argon's 50. It costs $1.50 per million input tokens and $7.50 per million output tokens. Google also added "Orchestrator" to its coding tool Antigravity. It switches between models in one session, like a manager handing easy jobs to a quick helper. Google says this reached near-Carbon success on a test while using 24% less quota and finishing 19% faster. Hydrogen also powers an upgraded Google Search.

**Why it matters:** Cheap, fast models make AI agents affordable to run all day. Using a big model only for hard parts may become the normal pattern.

**New words:** **Token** — a small chunk of text that AI models read and write; prices are set per chunk · **Agent** — an AI program that plans and does several steps by itself · **Context window** — how much text a model can look at at once (here, 1 million tokens)

## 2. Cloudflare picks a rare way for computers to agree, with no boss needed
*Cloudflare* · Backend

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-13/2.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-13/2.mp4"></video>

**In one line:** Cloudflare is building a worldwide system whose machines agree on shared data, and it chose an algorithm that keeps going even if its leader fails.

**What happened:** Many machines must sometimes agree on one shared truth. This is called consensus. Popular methods such as Raft use one leader. If the leader is slow or cut off, everything stops until a new one is elected. Elections can even fight each other and keep failing, after the original problem is gone. In 2020 a faulty network switch made a Cloudflare dashboard run 80 times slower for six hours. For its new system, Meerkat, Cloudflare chose QuePaxa. In QuePaxa the leader is optional. Anyone can propose a value, and proposers adopt the best-ranked idea they see instead of fighting. Cloudflare says over 95% of decisions are made quickly by the leader. When the leader fails, the system slows to as little as a third of its speed but never stops.

**Why it matters:** The internet has sudden delays. Systems that don't depend on one boss, or on guessing who has failed, stay up in bad weather.

**New words:** **Consensus** — many machines agreeing on one answer even if some fail · **Leader** — the one machine allowed to make decisions · **Replica** — a copy of the data on another machine · **Metastable failure** — a problem that keeps itself going even after its cause is gone

## 3. LinkedIn builds its own deployer instead of using Argo CD
*InfoQ (about LinkedIn)* · Cloud

<video controls playsinline preload="none" poster="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-13/3.jpg" src="https://vishwajeet-13.github.io/eng-digest-videos/2026-11-13/3.mp4"></video>

**In one line:** LinkedIn replaced a popular deployment tool with its own, and failures caused by the deployment system fell sharply.

**What happened:** Argo CD is a tool that makes a Kubernetes cluster match what is saved in Git. Kubernetes runs apps across many computers. LinkedIn ran one Argo CD per cluster and hit problems at scale. One app's activity could slow syncing for all apps. On a cluster with over 80,000 pods, syncs took more than 10 minutes. The new system gives each deployment its own short-lived pod, with no shared state. It replaces whole objects instead of patching them, and compares the live, old and new versions to spot drift. It now covers over 250 clusters and 4,000 services, with 100,000+ deployments a week. LinkedIn says deployment-system failures fell from 925 to 63. Failed deployments are now found in 2.45 minutes instead of 16.1. LinkedIn says the new engine isn't the only reason for the improvement. The engine is internal.

**Why it matters:** Tools that work well for a small setup can struggle at huge scale. Isolating each job can be better than tuning one shared program.

**New words:** **Kubernetes** — software that runs and manages apps across many computers · **GitOps** — deploying by keeping the wanted setup in Git and letting a tool match it · **Pod** — the smallest running unit in Kubernetes · **Drift** — when the live system no longer matches what was planned

## 4. Zillow sends 100 million notifications a day with one shared workflow system
*AWS Architecture Blog* · Backend

**In one line:** Zillow replaced many separate notification services with one configurable system built on AWS Step Functions.

**What happened:** Zillow sends over 100 million emails and push alerts daily. Before, more than 10 services each built its own campaigns, so work was repeated and behaviour differed. Now each message runs as its own short workflow on Step Functions Express, a managed AWS tool for chaining steps. Each step calls shared, reusable modules, and campaigns are set up in configuration instead of new code. A router reads a queue, can pause or replay campaigns, and can batch messages to cut cost. Zillow estimates the build took 9 development weeks versus 32 for a comparable in-house engine. Upkeep fell from about 8 hours a week to 2.

**Why it matters:** Doing common steps once, and describing the rest in settings, lets teams launch new features faster.

**New words:** **Workflow** — a series of steps run in order · **Idempotent** — safe to run twice with the same result · **Queue** — a waiting line for messages · **Batching** — handling many items together

## 5. Rust 1.100 adds a "wait a few days" safety setting for new packages
*Rust Blog* · Security

**In one line:** The new Rust release can skip package versions that were published only moments ago.

**What happened:** Bad package versions are often caught within hours or days. Cargo, Rust's package manager, can now wait. You set `global-min-publish-age = "3 days"` and it skips newer versions, and tells you what it held back. The release also finally stabilizes the "never type" (`!`) after 10 years and five failed attempts. It marks code that never returns a value. It also adds a way to plug in custom memory allocators, a `DropGuard` helper to run cleanup code, and warnings for unused dependencies. The Rust team says waiting is not a full defence, so keep reviewing updates.

**Why it matters:** A short delay is a cheap way to avoid many poisoned packages.

**New words:** **Dependency** — code from someone else that your project uses · **Supply chain attack** — hiding bad code in something many people download · **Allocator** — the part that hands out memory
