## 1. A bug hidden in three places made Google's Kubernetes servers time out
*InfoQ (from the Google Cloud blog)* · Cloud

**In one line:** Google spent weeks finding why some programs could not reach the control centre of their Kubernetes clusters, and the final fix was a patch to Linux itself.

**What happened:** A customer ran several GKE clusters (Google's managed Kubernetes) with a private link called Private Service Connect. Programs sometimes timed out when they tried to talk to the Kubernetes API server. Packet captures showed the server answering new connection requests with old, leftover replies from connections that had already closed. Google found three bugs working together: packets arriving out of order in Private Service Connect, a proxy called Envoy not closing connections cleanly, and a Linux kernel bug that threw away some out-of-order "I'm done" (FIN) packets. That left connections stuck forever in a waiting state called FIN_WAIT_2. About 800 developers were blocked from deploying to production. Google rolled back a change, fixed the proxy handling, and the kernel patch reached GKE customers in version 1.33.5 and later.

**Why it matters:** It shows that a problem can look the same at every layer, and only careful packet captures reveal that several small bugs are combining.

**New words:** **Packet capture** — a recording of the small messages sent over a network · **Kernel** — the core part of an operating system, like Linux · **TCP** — the set of rules computers use to make a reliable connection · **FIN_WAIT_2** — a TCP state where one side has said "I'm done" and waits for the other side to say the same

## 2. Valkey swaps a 1990 data structure for one that saves memory
*Valkey blog* · Backend

**In one line:** Valkey's sorted sets (lists kept in score order) now use a tree called fbtree instead of a skiplist, using 36–43% less memory per member.

**What happened:** A sorted set must always keep its items in order. Valkey used a skiplist, where every item sits in its own separate memory spot linked by pointers. Those pointers cost about 37 bytes per item before you even store the item's name. Chasing them also makes the processor wait on slow memory again and again. The new fbtree packs up to 61 items into one block, like a bookshelf instead of loose sheets of paper. In a test with 5 million members, overhead per member fell from 50.3 to 28.5 bytes (sequential inserts) or 32.0 bytes (random inserts). Adding or updating a score became up to 105% faster in the team's benchmark.

**Why it matters:** For databases that hold everything in memory, saving a few bytes per item adds up to many megabytes, and nothing changes for the people using it. The one visible change is that `OBJECT ENCODING` now says `btree`, not `skiplist`.

**New words:** **Skiplist** — a sorted list where each item points to others to jump ahead quickly · **B+ tree** — a tree that stores many items per block, so fewer jumps are needed · **Cache miss** — when the processor must fetch data from slow main memory · **Valkey** — a fast in-memory database, like Redis

## 3. Inkling 2 Mini: a small AI model that thinks in loops
*Thinking Machines Lab* · AI

**In one line:** A new open model that fits on a laptop reuses its middle layers three times per word so it can reason more without writing more.

**What happened:** Thinking Machines released Inkling 2 Mini with open weights, meaning anyone can download it. It has 26.4 billion total parameters but only 3.4 billion are active at a time, and it takes about 20 GB of memory. It is a "looped transformer": the middle layers run three times for every token (word piece), so it can think more without writing out all its thinking. The company says it beats every open model under 100 billion parameters on coding tests like DeepSWE v1.1 (48.2%). It also ran offline on a MacBook Pro and built a flight simulator. It is weaker at long multi-turn chat and at following many strict rules, and looping does not help it store more facts.

**Why it matters:** Small models that run on your own computer can now do serious coding work, without sending your data anywhere.

**New words:** **Open weights** — the trained model files are public to download · **Parameter** — one learned number inside a model; more usually means a bigger model · **Token** — a small piece of text a model reads or writes · **Looped transformer** — a model that runs some of its layers several times

## 4. OpenAI uses AI agents to find and fix slowdowns in ChatGPT
*OpenAI* · AI

**In one line:** OpenAI built the "Performance Factory", where Codex agents investigate speed problems, propose fixes and check the results.

**What happened:** When a speed alert fires, the system opens a task. One agent works out what got slower and why, a second agent tries to prove that diagnosis wrong, and a third writes a fix for an engineer to review. After the fix ships, another agent checks that speed is back to normal. In just over three months it tracked more than 1,700 investigations and found the root cause in over 600. When OpenAI checked 100 root-cause suggestions by hand, 70% were accurate. They say writing a good fix is harder than finding the cause, so engineers still review every change.

**Why it matters:** It shows a real pattern for using AI agents at work: small steps, a second agent to challenge the first, and a human sign-off.

**New words:** **Regression** — something that used to work well and got worse after a change · **Agent** — an AI that takes steps on its own using tools · **Root cause** — the real reason a problem happens · **Adversarial review** — a second reviewer trying to disprove the first one's answer

## 5. Uber moved most of its translation cache to disk and cut memory by over 90%
*InfoQ (from Uber Engineering)* · Backend

**In one line:** Uber keeps only the lookup keys and the popular values in memory, and puts the rest on disk.

**What happened:** Uber's Go services cache translations (app text in many languages). Memory profiling showed garbage collection, the automatic memory cleanup, used over 20% of CPU in some services. Refreshing the cache built a second copy in memory, which sometimes ran services out of memory. Uber's fix keeps every key in memory but stores values in files on disk, split into 256 shards. One dataset went from about 800 MB to about 40 MB of metadata. In another case memory fell from 2.7 GB to 750 MB. The hit rate stayed above 99.9%, and disk misses stayed under 100 microseconds at p99.

**Why it matters:** If a cache is mostly unused, you don't need to hold all of it in expensive memory.

**New words:** **Cache** — a quick-access store for data you use often · **Garbage collection** — automatic cleanup of memory the program no longer needs · **Shard** — one slice of a bigger data set · **p99 latency** — the time within which 99 out of 100 requests finish

## 6. A critical GnuPG library bug: one long name can crash mail apps
*GnuPG announcement* · Security

**In one line:** GPGME, the library many programs use to talk to GnuPG, had a "double free" bug, so people should update to 2.3.1 now.

**What happened:** An OpenPGP key (used to sign and encrypt) with a very long user ID can make GPGME free the same memory twice. That could leak data from apps, and attackers running their own code can't be ruled out. The cause: the code grew a buffer from 1024 bytes but only saved the new address at the end. If it stopped early, the old, freed address stayed in use. GitLab told GnuPG on 12 November. Disclosure was planned for 25 November, but was moved to 20 November because of another bug, Ruby2Shell. Affected software includes Gpg4win, most mail clients, many XMPP clients, Samba and Flatpak.

**Why it matters:** Many apps use this library without you knowing, so one fix is needed in many places.

**New words:** **Double free** — freeing the same piece of memory twice, which can corrupt a program · **Remote code execution (RCE)** — an attacker running their own code on your machine · **CVE** — a public ID number for a known security hole · **Buffer** — a temporary block of memory for data
